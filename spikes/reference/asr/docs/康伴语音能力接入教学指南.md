## 第一课 · 全景图：一段语音的旅程

### 1.1 先认识几个关键词

| 缩写 | 全称 | 一句话解释 | 类比 |
|------|------|-----------|------|
| **VAD** | Voice Activity Detection | 语音活动检测，判断「此刻有没有人在说话」 | 楼道里的声控灯，有声音就亮 |
| **ASR** | Automatic Speech Recognition | 自动语音识别，把声音转成文字 | 你对着微信说话，它转成文字发出去 |
| **Speaker Embedding** | 说话人嵌入 | 把一段声音压缩成一串数字（向量），代表「这个人的声音特征」 | 每个人指纹不同，声音也有独特「指纹」 |
| **Speaker Verification** | 说话人验证 | 比较两段声音是不是同一个人 | 解锁手机时的指纹比对 |
| **WebSocket** | WebSocket | 浏览器和服务器之间的实时双向通信协议 | 普通 HTTP 像发短信（请求-响应），WebSocket 像打电话（一直在线，两边都能随时说话） |
| **WSS** | WebSocket Secure | 加了 TLS 加密的 WebSocket，跟 HTTPS 对应 | 加密版的电话，别人窃听不到 |

### 1.3 分层设计思想（为什么要这样拆）

**问题：为什么不直接在浏览器里放声纹和 ASR 模型？**

| 方案 | 问题 |
|------|------|
| 全部放浏览器 | 模型太大（FunASR 几百 MB），浏览器下载慢；算力不够，手机卡爆；每次换模型要重新部署前端 |
| 全部放后端 | 用户一开口就把音频上传，浪费带宽；服务器要一直处理静音；用户体验差（说话开头几个字丢失） |
| **康伴的做法** | VAD 放浏览器端（很小，只需判断有没有人说话），静音时不传音频；VAD 检测到人声了再按需上传给后端；后端做重活（声纹验证 + ASR） |

**核心思想：前端做轻量决策，后端做重型计算。**

## 第三课 · 音频采集：把声音变成数据

### 3.1 什么是 PCM、采样率、16 位？

人的声音是连续的空气震动波。电脑要处理它，得把它变成一串数字——这就叫**模拟信号→数字信号**。

三个关键概念：

| 术语 | 含义 | 康伴 demo 里的值 |
|------|------|-----------------|
| **采样率** (sample rate) | 每秒采多少个点 | 16000 Hz（每秒 16000 个采样点） |
| **位深** (bit depth) | 每个点用多少位表示振幅 | 16 bit（-32768 到 32767，叫 PCM16） |
| **声道数** | 几路声音 | 1（单声道，人声识别够用） |

**16kHz PCM16 单声道** = 每秒产生 16000 × 2 = **32000 字节**。

> 🎯 为什么选 16kHz？人声的主要能量在 300-3400Hz，采样率选两倍最高频率就够了（奈奎斯特定理），16kHz 留了余量。ASR 领域基本都用 16kHz。

### 3.2 康伴 demo 的前端采集方案：AudioWorklet

浏览器有好几种录声音的 API：

| API | 特点 |
|-----|------|
| `MediaRecorder` | 直接输出压缩好的 mp3/webm，不适合实时处理 |
| `ScriptProcessorNode` | 老方案，有延迟 |
| **`AudioWorklet`** ✅ | 新方案，独立线程、低延迟，康伴用的这个 |

代码在 [audio-worklet.js](file:///d:/2605/14.项目实战/kangban/asr/src/asr/web/audio-worklet.js)：

```javascript
class Capture extends AudioWorkletProcessor {
  constructor() {
    super();
    this.phase = 0;   // 重采样累积相位
    this.sum = 0;     // 均值累积
    this.count = 0;   // 当前均值的采样点个数
    this.out = new Int16Array(960);  // 60ms 的 PCM16 帧
    this.index = 0;
  }

  process(inputs) {
    const input = inputs[0]?.[0];
    if (input) for (const value of input) {
      this.sum += value;
      this.count++;
      this.phase += 16000;          // 目标采样率
      if (this.phase >= sampleRate) { // sampleRate 是麦克风的实际采样率（通常 44100 或 48000）
        this.phase -= sampleRate;
        this.out[this.index++] = Math.round(Math.max(-1, Math.min(1, this.sum / this.count)) * 32767);
        this.sum = 0; this.count = 0;
        if (this.index === 960) {   // 960 个点 = 60ms (960/16000)
          this.port.postMessage(this.out.buffer, [this.out.buffer]);
          this.out = new Int16Array(960);
          this.index = 0;
        }
      }
    }
    return true;
  }
}
```

这段代码做了两件事：
1. **重采样**：把设备的 44100/48000 Hz 降成 16000 Hz（简单的平均插值）
2. **分块**：每攒够 960 个采样点（60ms）就通过 `postMessage` 发给主线程

主线程在 [app.js](file:///d:/2605/14.项目实战/kangban/asr/src/asr/web/app.js) 里这样启动：

```javascript
// 申请麦克风权限
media = await navigator.mediaDevices.getUserMedia({
  audio: { channelCount: 1, echoCancellation: true, noiseSuppression: true },
  video: false
});

// 创建 AudioContext，加载 worklet
context = new AudioContext();
await context.resume();
await context.audioWorklet.addModule('/audio-worklet.js');

// 连接：麦克风 → worklet → 目的地（可选）
const source = context.createMediaStreamSource(media);
worklet = new AudioWorkletNode(context, 'capture');
worklet.port.onmessage = e => onAudio(e.data);  // 收到 60ms PCM16 数据块
source.connect(worklet);
worklet.connect(context.destination);
```

## 第四课 · VAD：让机器知道「什么时候有人在说话」

### 4.1 为什么需要 VAD？

假设你在餐厅里用语音助手：
- 你说话的总时长可能只有 3 秒
- 但你从坐下到站起来一直开着麦克风，总时长 30 秒
- 如果把 30 秒全部发给后端 ASR，浪费 90% 带宽，而且识别率会被背景噪声拖垮

**VAD 的作用：只在有人说话的时间段把音频送去识别。**

### 4.2 端侧 VAD vs 服务端 VAD

| 位置 | 优点 | 缺点 |
|------|------|------|
| **服务端** | 模型更大更准 | 静音也得传，浪费带宽；检测有延迟 |
| **前端/端侧** | 静音不传，省带宽；即时响应 | 模型要小，精度稍低 |
| **两者结合** | 前端粗筛，后端精分 | 复杂度高 |

康伴用的是**端侧 VAD + 后端 VAD 都开**：
- 浏览器先做粗筛（TEN-VAD WASM），静音不传
- FunASR 内部还有 FSMN-VAD 做分句

### 4.3 康伴 demo 的端侧 VAD：TEN-VAD (Sherpa-ONNX WASM)

#### 4.3.1 为什么是 WASM？

WASM (WebAssembly) 是一种能在浏览器里跑的二进制格式，性能接近原生 C/C++。Sherpa-ONNX 把 C++ 的 VAD 模型编译成 WASM，直接在浏览器里推理——**音频永远不出本机**。

#### 4.3.2 BrowserTenVad 类的使用

封装在 [ten-vad.js](file:///d:/2605/14.项目实战/kangban/asr/src/asr/web/vad/ten-vad.js)，康伴主页面这样初始化：

```javascript
// Module 是 Emscripten 胶水脚本的全局对象，需要先加载
detector = new BrowserTenVad(Module, {
  threshold: .5,     // 语音概率阈值，越高越严格
  silence: .8,       // 静音 0.8 秒才认为说完了
  minSpeech: .25,    // 最短 0.25 秒才算语音
  maxSpeech: 30      // 最长 30 秒强制截断
});

// 监听事件
detector.addEventListener('speechstart', beginUtterance);
detector.addEventListener('speechend', endUtterance);

// 喂音频（每 60ms 喂一块）
const pcm = new Int16Array(data);  // PCM16
detector.feed(Float32Array.from(pcm, x => x / 32768));  // 转成 [-1, 1] 浮点

// 用完释放
detector.flush();
detector.free();
```

#### 4.3.3 四个参数的调参指南

| 参数 | 当前值 | 调高效果 | 调低效果 |
|------|--------|---------|---------|
| `threshold` | 0.5 | 过滤环境噪音更狠，但小声说话可能检测不到 | 任何轻微声音都触发，容易误检 |
| `silence` | 0.8 | 容忍句中停顿（比如想事情），长句不会被切 | 快速切句，但说话稍微停一下就被截断 |
| `minSpeech` | 0.25 | 丢弃短促的咳嗽、敲击声 | 一切声音都当作说话开始 |
| `maxSpeech` | 30 | 允许更长连续讲话 | 强制截断长句 |

**实操建议**：先用 demo 的默认值（threshold=0.5, silence=0.8），实际测试后再调。如果你发现「说话中间稍微停顿就被截断了」，把 `silence` 调到 1.0-1.5；如果你发现「背景里电视声也触发了」，把 `threshold` 调到 0.6-0.7。

### 4.4 浏览器加载 WASM 的坑

看 [index.html](file:///d:/2605/14.项目实战/kangban/asr/src/asr/web/index.html) 的脚本顺序：

```html
<script src="/vad-assets/sherpa-onnx-vad.js"></script>       <!-- WASM 胶水 -->
<script src="/vad/ten-vad.js"></script>                      <!-- BrowserTenVad 封装 -->
<script src="/app.js"></script>                               <!-- 主业务逻辑 -->
<script src="/vad-assets/sherpa-onnx-wasm-main-vad.js"></script>  <!-- 最后加载 WASM 二进制 -->
```

[app.js#L7-L11](file:///d:/2605/14.项目实战/kangban/asr/src/asr/web/app.js#L7-L11) 里定义了全局 `Module`：

```javascript
var Module = {
  locateFile: path => '/vad-assets/' + path,
  onRuntimeInitialized: () => {
    try {
      const v = new BrowserTenVad(Module);  // 空跑一次验证模型可用
      v.free();
      loaded = true;
      controls();
    } catch (e) { showError(e); }
  },
  onAbort: reason => { showError(Error('端侧 VAD 模型加载失败：' + reason)); },
};
```

**关键点**：`Module` 必须在 WASM 脚本**之前**定义好，WASM 胶水脚本加载时会找全局 `Module` 配置。

## 第五课 · WebSocket：实时对话的高速公路

### 5.1 为什么不用 HTTP？

| 场景 | HTTP | WebSocket |
|------|------|-----------|
| 浏览器 → 服务器 发音频 | ✅ 每次 POST 一块 | ✅ 随时发 |
| 服务器 → 浏览器 推识别结果 | ❌ 只能轮询 | ✅ 随时推 |
| 建立连接的开销 | 每次请求都要握手 | 只握一次 |
| 适合场景 | 文件上传下载 | 实时对话、直播、协作 |

**简单理解**：HTTP 是寄信（写一封信、等回信、再写下一封），WebSocket 是打电话（接通后双方随时说话）。

### 5.2 康伴 demo 的两个 WebSocket

```
┌───────────┐                    ┌──────────────┐                    ┌───────────────┐
│  浏览器    │ ──── /ws/audio ──▶ │  FastAPI      │ ──── WSS ──────▶ │  FunASR        │
│  (app.js) │ ◀── JSON 事件 ─── │  (webapp.py)  │ ◀── JSON ────── │  Docker 容器    │
└───────────┘                    └──────────────┘                    └───────────────┘
```

#### 5.2.1 浏览器 → FastAPI：`/ws/audio`

浏览器发起 WebSocket 连接：

```javascript
const ws = new WebSocket(`${location.protocol==='https:' ? 'wss' : 'ws'}://${location.host}/ws/audio`);
```

**第一步：握手消息（JSON）**

```jsonc
// 录入声纹时
{
  "action": "enroll",
  "name": "我的名字",
  "threshold": 0.55,
  "endpointing": "client"      // 端点检测由客户端（浏览器 VAD）决定
}

// 开始识别时
{
  "action": "listen",
  "threshold": 0.55,
  "endpointing": "client",
  "token": "之前声纹验证通过后拿到的 token"  // 首句验证后才有
}
```

**第二步：传音频（二进制）**

```javascript
ws.send(audioChunk);  // ArrayBuffer，960×2=1920 字节的 PCM16
```

**第三步：发停止信号（JSON）**

```json
{ "action": "stop" }
```

**后端返回的事件（JSON）**

| type | 含义 | 示例 |
|------|------|------|
| `ready` | 后端就绪，开始发音频 | `{"type": "ready"}` |
| `verification` | 声纹验证结果 | `{"type": "verification", "accepted": true, "score": 0.78, "token": "...", "expires_at": 1730000000}` |
| `state` | 会话状态 | `{"type": "state", "state": "recognizing"}` |
| `transcript` | 识别结果 | `{"type": "transcript", "mode": "2pass-online", "text": "你好", "is_final": false}` |
| `done` | 会话正常结束 | `{"type": "done"}` |
| `error` | 出错了 | `{"type": "error", "message": "..."}` |

#### 5.2.2 FastAPI → FunASR：WSS 带 TLS

后端连接 FunASR Docker 的 WSS 服务，因为容器用了自签名证书，所以设置 `FUNASR_INSECURE=1` 跳过校验：

```python
# voice.py 里的 open_asr()
ws = await connect(
    self.config.url,  # wss://127.0.0.1:10096
    ssl=context,  # SSLContext，insecure 时关闭校验
    subprotocols=["binary"],
)
# 握手后发 FunASR 的协议初始化 JSON
await ws.send(
    json.dumps(
        {
```

## 第六课 · 声纹识别：听见你的声音就知道是你

### 6.1 什么是说话人嵌入（Speaker Embedding）？

想象给你的声音做一个「特征提炼」：
- 你说一句 3 秒的话 → 模型输出一个 192 维的浮点数向量（CAMPPlus 模型）
- 同一个人说不同的话 → 向量很相近（余弦相似度高）
- 不同的人 → 向量差异大

**验证时就是算两个向量的余弦相似度，超过阈值就认为是同一个人。**

### 6.2 康伴 demo 怎么做声纹的？

#### 6.2.1 模型：CAMPPlus

路径：`funasr-runtime-resources/models/sherpa-onnx/3dspeaker_speech_campplus_sv_zh-cn_16k-common.onnx`

加载和使用在 [voice.py#L63-L91](file:///d:/2605/14.项目实战/kangban/asr/src/asr/voice.py#L63-L91)：

```python
class SpeakerGate:
    def __init__(self, config):
        path = (
            Path(config.model_dir)
            / "3dspeaker_speech_campplus_sv_zh-cn_16k-common.onnx"
        )
        self.extractor = sherpa_onnx.SpeakerEmbeddingExtractor(
            sherpa_onnx.SpeakerEmbeddingExtractorConfig(model=str(path), num_threads=1)
        )

    def embedding(self, audio):
        """从一段 16kHz float32 音频中提取说话人向量"""
        stream = self.extractor.create_stream()
        stream.accept_waveform(RATE, np.ascontiguousarray(audio, dtype=np.float32))
        stream.input_finished()
        if not self.extractor.is_ready(stream):
            raise ValueError("Not enough speech")
        return normalize(self.extractor.compute(stream))
```

#### 6.2.2 声纹录入（Enrollment）

录入就是「让模型认识你」。你录几段干净的语音，提取 embedding 存起来：

```python
def enroll(self, name, files, destination):
    embeddings = []
    for filename in files:
        # 读 WAV → 转 float32 [-1, 1]
        audio = read_wav_to_float32(filename)
        embeddings.append(self.embedding(self.speech_only(audio)))

    # 多段取平均，得到更稳定的声纹档案
    record = {
        "name": name,
        "model_sha256": self.fingerprint,
        "embedding": normalize(np.mean(embeddings, axis=0)).tolist(),
    }
    Path(destination).write_text(json.dumps(record))
```

录入后的 `speaker.json` 长这样：

```json
{
  "name": "张三",
  "model_sha256": "abc123...",
  "embedding": [0.023, -0.156, 0.089, ..., 0.034]   // 192 个浮点数
}
```

#### 6.2.3 实时验证（Verification）

用户说话时，后端边收音频边攒「有效语音」，攒够约 2 秒后提取 embedding，和已存的参考向量做比较：

```python
# voice.py run() 里的核心验证逻辑
embedding = self.embedding(np.concatenate(speech))
score = float(np.dot(reference, embedding))  # 余弦相似度（向量已归一化）
verified = score >= self.config.threshold  # threshold 默认 0.55
```

**阈值调参**：
- 默认 0.55 是通用值
- 太高（如 0.7）→ 家人也过不了
- 太低（如 0.4）→ 可能被别人冒充
- **实测**：同一人两段完整音频约 0.57，仅取前两秒约 0.52；不同人通常 < 0.45

### 6.3 快速接到自己的项目

```python

# 录入（命令行）
# uv run python -m asr.voice enroll --name 你 --wav 你的录音.wav --profile data/speaker.json

# 代码里使用

# 从 WAV 录入

print(emb.shape)  # (192,)
```

### 6.4 关于 token 机制（为什么有它）

问题来了：每次说话都做声纹验证吗？
- 如果一句话都要等 2 秒才通过，体验就很差
- 如果每句话都验证，计算量也大

**康伴的做法**：首句话做声纹验证 → 通过后签发一个临时 token（默认 300 秒有效）→ 后续句子直接带 token 跳过验证 → token 过期后下一句自动重新验证

这个机制在 [webapp.py#L45-L86](file:///d:/2605/14.项目实战/kangban/asr/src/asr/webapp.py#L45-L86) 的 `SessionTokens` 类里实现。

## 第七课 · ASR：把声音变成文字

### 7.1 康伴用的 ASR：FunASR 双通路

FunASR 是阿里达摩院开源的 ASR 工具包，康伴用的是它的 **2pass（双通路）流式识别**：

| 通路 | 模型 | 延迟 | 准确度 | 用途 |
|------|------|------|--------|------|
| **Online**（在线） | `speech_paraformer-large_asr_nat-...-online` | 几十毫秒 | 稍低 | 实时字幕，边说边出字 |
| **Offline**（离线/修正） | `speech_paraformer-large-vad-punc_asr_nat-...` | 几百毫秒 | 高，带标点 | 最终结果，更准确还有标点 |

为什么叫双通路？FunASR 内部两条模型同时跑：
1. 在线模型实时吐出初步文字（`2pass-online`）
2. 离线模型等句子结束后重新整段识别，产出带标点的最终文字（`2pass-offline`）

### 7.2 Docker 容器配置

在 [compose.yaml](file:///d:/2605/14.项目实战/kangban/asr/compose.yaml) 中，容器用了 5 个模型目录：

```yaml
command:
  - --download-model-dir  /workspace/models
  - --vad-dir            damo/speech_fsmn_vad_zh-cn-16k-common-onnx       # FunASR 内部 VAD
  - --model-dir          damo/speech_paraformer-large-vad-punc_asr_nat-...  # 离线模型
  - --online-model-dir   damo/speech_paraformer-large_asr_nat-...-online    # 在线模型
  - --punc-dir           damo/punc_ct-transformer_zh-cn-common-vad_realtime-...  # 标点模型
  - --lm-dir             damo/speech_ngram_lm_zh-cn-ai-wesp-fst              # 语言模型
  - --port               "10095"                                             # 容器内端口
```

映射到主机 `10096:10095`，所以后端连 `wss://127.0.0.1:10096`。

### 7.3 FunASR WebSocket 协议

后端 `voice.py` 发送的初始化消息：

```json

  "mode": "2pass",
  "chunk_size": [5, 10, 5],
  "chunk_interval": 10,
  "encoder_chunk_look_back": 4,
  "decoder_chunk_look_back": 1,
  "audio_fs": 16000,
  "wav_format": "pcm",
  "is_speaking": true,
  "itn": true

```

FunASR 返回的识别结果：

```json

{"mode": "2pass-online", "text": "你好世界", "is_final": false}

// 离线修正结果（句尾更准、带标点）
{"mode": "2pass-offline", "text": "你好，世界。", "is_final": true}
```

**前端收到结果怎么处理？** 看 [app.js#L54](file:///d:/2605/14.项目实战/kangban/asr/src/asr/web/app.js#L54)：

```javascript
if (e.mode === '2pass-offline') {
  finalText += e.text || '';   // 最终结果，累积追加
  liveText = '';                // 实时结果清空
} else if (e.mode === '2pass-online' || e.mode === 'online') {
  liveText += e.text || '';    // 实时结果，累积追加
}
```

### 7.4 可以换其他 ASR 吗？

当然可以。康伴后端在 `voice.py` 里封装了对 FunASR 的 WSS 调用，如果你想用别的 ASR：

| 方案 | 怎么换 |
|------|--------|
| 阿里云 / 腾讯云 ASR | 把 `open_asr()` 里的 WSS 地址和协议换成云厂商的，其他逻辑不变 |
| FunASR 模型降级 | 改 `compose.yaml` 的 model-dir，换成更小的模型（如 paraformer-small） |
| 完全换引擎 | 重写 `open_asr()` 和 `receive()` 两个函数即可，封装的 SpeakerGate 不动 |

## 常见问题排查

### Q1：Docker 容器启动报错 "model not found"

检查 `compose.yaml` 里模型路径是否和容器内的 `/workspace/models/` 对得上。容器挂载的是 `./funasr-runtime-resources/models:/workspace/models`，启动前确认本地 models 目录存在。

### Q2：浏览器提示「无法连接语音服务」

检查：
1. Docker 容器是否在跑：`docker compose ps`
2. 端口是否通：`netstat -ano | findstr 10096`
3. `FUNASR_INSECURE=1` 是否设置

### Q3：声纹验证总是不通过

1. 检查录入的录音是否干净（无背景噪声、离嘴 10-20cm）
2. 试试调高阈值还是调低？→ **调低**（更宽容）
3. 可以用多段录音录入：`--wav 文件1 --wav 文件2 --wav 文件3`，取平均更稳定
4. 默认阈值 0.55，试试调到 0.45

### Q4：VAD 不触发或者乱触发

打开 `/vad/` 独立页面调试。调 `threshold` 参数：
- 乱触发（电视声、风声也检测到）→ 调高 threshold
- 不触发（小声说话检测不到）→ 调低 threshold
- 句中停顿就截断 → 调高 silence

### Q5：识别速度慢

1. 第一次使用 Docker 模型会加载几秒，之后就快了
2. 如果 CPU 核数少，可以把 `compose.yaml` 里的 `--decoder-thread-num` 调大
3. 检查是否有其他程序占满 CPU

### Q6：TLS / 证书问题

FunASR 容器用的是自签名证书。本地开发设置 `FUNASR_INSECURE=1` 跳过校验即可。正式环境请替换为可信证书，并使用 `--ca-file` 指定 CA。

### Q7：Windows 下 `uv run voice-web` 启动报错

- 确认 Python 版本 ≥ 3.13（`python --version`）
- 确认 uv 已安装（`uv --version`）
- 确认 `uv sync` 已执行过
