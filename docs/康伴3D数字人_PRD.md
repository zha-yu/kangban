## 1. 背景与目标

### 1.1 背景

「康伴」面向 CCRC 康养社区的**教学模拟场景**，在长者卧室的"平板"上以 3D 数字人、语音交互和大字幕为入口，连接长者、护工、医生、家属与管理员。本版验证的是端到端业务闭环与 Agent 工程能力，**不是**可直接用于真实照护的生产系统。

规模口径：单社区 800–1500 位长者是**业务背景与未来目标规模**，不是本版的并发容量。本版验收负载为：单机 Docker、1 路活跃语音、≤10 个后台在线用户。

### 1.2 产品定位

一套**可演示、可测试、可观测、可降级**的教学 MVP。一句话架构：

> 语音（WebRTC 全双工主模式 / 按住说话降级）→ ASR → 三级路由（安全规则 → Laya 分类器 → 主控 Agent）→ 工具/子图 → TTS → WebRTC 音频轨 / HTML 页面播放 + 大字幕。

外部系统边界：**天气 API 是唯一真实外部接口**；微信通知、HIS/工单服务全部为 Mock 服务；不接真实短信、电话、微信、医院。

关键口径（全文档统一，禁止混用）：

- **已服自报**：长者通过语音或按钮表达"已服用"，不代表系统证实实际服药。
- **提醒送达**：HTML 页面成功渲染提醒卡片/播报完成并回调回执，不代表长者已听到、看到或理解。
- **红色/黄色事件**：教学演示风险等级，不是医疗诊断。
- **System Two**：开放对话大模型，无权覆盖安全规则或执行高风险写操作。

### 1.3 成功标准

- 所有 P0 功能有实现、有测试、有验收记录，每条 P0 均可追踪到验收用例。
- 用药、健康、告警、日报四条业务链路端到端可运行、可重复验收。
- 急症规则不被大模型覆盖、降级或延迟；红色事件 2 分钟升级。
- `missed_unconfirmed`（已送达未确认）与 `notification_failed`（通知失败）在任何场景不混淆，不虚构送达或实际服药。
- 三级路由、LangGraph、MCP、Langfuse、教学级声纹等课程技术成果全部交付并通过对应验收。
- 3D、天气或大模型故障时，核心功能有明确降级行为，不白屏。

**本版仅用固定模拟数据验证流程正确性，不以模拟数据计算出的任何比例（确认率、完成率等）作为真实运营效果证明。** 大纲中的运营指标（用药确认率 ≥85%、日均对话 ≥3 次等）保留为后续试点观察方向，**不作为本版验收条件**。

### 1.4 非目标清单

本版不做：

- 真实 HIS、医保、医院、急救、真实微信对接；医疗诊断、处方、剂量调整、补服建议。
- 生产级声纹身份认证（防录音重放、语音合成对抗、跨信道鲁棒性与 FAR/FRR 承诺）、说话人分离（Diarization）、访客身份自动识别、声纹模型微调。
- 连续监听（always-on 无差别监听）。本版采用 **唤醒词激活**（端侧关键词检测，默认唤醒词"小伴"，命中后才建连上传，见 §2.2）+ **WebRTC 全双工对话**（呼叫按钮 / 外呼到达建连）+ **反向 WebRTC 外呼**（主动用药提醒）；**唤醒词已定为 P0（2026-11-06 主理人裁决）**，AC-42 参与验收（与大纲 §3.2"喊一声小伴"/§11.1 验收 ≤1.5s 对齐）；always-on 无差别连续监听仍为非目标（隐私：唤醒词检测在端侧，未命中时原始音频不出端）。
- **强制**采集真实个人数据（敏感字段一律可选填写、允许跳过，默认使用虚构演示数据，见 §1.5）。
- 电影、新闻为 P2 可选；家属日程为非目标。
- 记忆公私共享：本版长期记忆**仅本人可见**（无 shared 共享记忆分类），不对医生/护工开放记忆查看；健康相关信息以结构化健康记录为准。
- 多社区 SaaS、生产级高可用、800–1500 人并发、真实社区试点与商用准入。

### 1.5 数据与隐私策略

| 数据类别            | 策略                                                                              |
| --------------- | ------------------------------------------------------------------------------- |
| 姓名、房间、药单等演示基础数据 | 默认使用虚构演示数据，管理端可编辑                                                               |
| 病史、联系方式等敏感字段    | **可选填写、允许跳过**：前端提供选填入口，未填写时自动使用虚构占位数据，所有功能不受影响；已填写的数据本人/管理员可删除                  |
| 声纹注册语音          | 由**使用者本人现场录制**（首次使用声纹功能时页面引导录制 3 段，并告知用途）；仅存于本地教学环境，可随时删除；不依赖教师提供样本             |
| 运行时对话语音         | 语音交互必然经过系统处理（ASR），但**处理 ≠ 留存**：运行时原始音频默认不保存；如需短期保存调试，须独立开关、明确用途、自动删除，且不得用于训练或调优 |
| 健康数据            | 均为演示/自报数据，页面与日报固定标注"教学模拟信息，不构成医疗诊断"                                             |

## 2. 技术约束与总体架构

### 2.1 HTML 页面约束（硬性）

**本产品无真实平板硬件。** 所有前端均为 HTML 页面（浏览器模拟平板界面）：

| 主题     | 约束与实现方式                                                                                                                                                                                                                                                                                                                                                                            |
| ------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 长者端    | 称为"**长者端 HTML 页面（浏览器模拟平板界面）**"；React 单页应用；参考尺寸 10 英寸 1920×1080，浏览器全屏演示                                                                                                                                                                                                                                                                                                             |
| 前端框架   | **统一采用 React（Vite + React）**：长者端用 React + Tailwind CSS（便于大字号、大按钮定制），护工/医生/家属/管理后台用 React + 原生 CSS（`var()` 引用设计 token，不引第三方组件库）；3D 与音频仍用原生 API（three-vrm、getUserMedia/MediaRecorder），React 负责组件与状态管理。**工程组织：单仓库单 React 工程，Vite MPA 三入口**——`pad`（长者端）/ `console`（护工/医生/管理员合并，内部按角色分流）/ `family`（家属端），避免 pad 的 three-vrm 依赖进入 console/family 构建包。选型理由：多端均为状态较重的交互界面，样式统一收敛于 tokens.css 唯一真源（utility + token 变量）可显著提升 10 天工期内的开发效率 |
| 设备绑定   | 无真实硬件。"设备"= 管理员创建的**模拟设备 ID/凭证**（如 device-001）。每台模拟设备与一位长者 **1:1 绑定**（归属房间不变）；声纹匹配候选集=绑定长者本人（恒 1 位），双人间另一位长者使用其自己的设备（见 §3.2）。HTML 页面通过 URL 参数/本地凭证选择绑定的模拟设备，服务端仍校验绑定有效性。设备凭证机制保留（教学价值），明确为软件模拟                                                                                                                                                                                                     |
| 语音采集   | **主模式：WebRTC 全双工实时音频轨**——浏览器 `getUserMedia` 取麦克风轨道经 WebRTC 建连（按呼叫按钮或外呼到达触发），实时双向传输、支持打断插话；TTS 经 WebRTC 音频轨下发或 `<audio>` 播放。**降级模式：`MediaRecorder`/Web Audio 按住说话整段上传**（WebRTC 不可用 / NAT 穿透失败 / 浏览器不支持时降级，见 §2.2）。麦克风权限需 HTTPS 或 localhost，本地教学部署可行                                                                                                                                                                                                                                                   |
| 终端回执   | HTML 页面成功渲染提醒卡片 / 播报完成时，回调回执接口（`card_rendered` / `tts_finished`）。比真实硬件更直接可测                                                                                                                                                                                                                                                                                                        |
| 播报打断   | 前端停止 `<audio>` 播放并通知后端；打断后停止当前播报、保留当前业务状态                                                                                                                                                                                                                                                                                                                                          |
| 3D 数字人 | VRM 模型 + three.js（@pixiv/three-vrm）在 HTML 页面加载；口型同步用 TTS 音频能量近似驱动；加载失败或超 5 秒降级为静态头像（`<img>`），核心功能不白屏                                                                                                                                                                                                                                                                               |
| 媒体分发   | 戏曲音频、日报语音条等媒体文件以 URL 直连 nginx 静态文件服务，浏览器 `<video>/<audio>` 直接播放，无需 HLS、不经后端转发                                                                                                                                                                                                                                                                                                      |
| 家属端无障碍 | 家属端页面 375px 宽度下无横向滚动、正文字号 ≥16px（手机浏览场景）                                                                                                                                                                                                                                                                                                                                            |

### 2.2 语音链路技术决策：WebRTC 全双工 + 反向 WebRTC 外呼（P0）

**决策**：教学 MVP 语音链路采用 **唤醒词激活 + WebRTC 全双工实时音频**为主模式（唤醒词"小伴"端侧检测命中 → 建连 → 被动对话；反向 WebRTC 外呼主动提醒），**HTTP/WebSocket 按住说话整段上传**为降级模式（WebRTC 不可用时兜底）。**WebRTC 全双工对话与反向 WebRTC 外呼为 P0 必交**（对应大纲 Day 3–5 的 WebRTC 与语音闭环交付：信令 / STUN/TURN / aiortc / 流式 ASR/TTS / 口型 / 端到端延迟）；**唤醒词激活已定为 P0（2026-11-06 主理人裁决）**：AC-42 参与验收、列入不得裁减；唤醒词检测不可用时降为呼叫按钮（FR-UI-09）单一入口。

**双模式适用场景**：

| 模式 | 触发 | 适用场景 |
| --- | --- | --- |
| WebRTC 全双工（主，P0） | 长者点"呼叫"按钮建连 / 反向外呼到达自动接听建连 | 实时对话、打断插话、主动用药提醒外呼、低延迟 TTS 流式下发 |
| HTTP/WS 按住说话（降级，P0） | WebRTC 建连失败、ICE 协商失败、浏览器不支持、NAT 穿透不可用时自动切换 | 降级兜底，保证核心对话、用药、健康功能可用不白屏 |

**理由**：① 与大纲 v1.3 对齐——大纲一句话定位即"WebRTC 全双工语音"，Day 3–5 完整安排 WebRTC 与语音闭环，是课程技术成果的核心组成；② 反向 WebRTC 外呼承担主动用药提醒（数字人主动开口），比 WebSocket 下发页面播报更贴近真实"主动触达"语义，T+15 漏服升级等链路以外呼到达视为触达；③ 全双工低延迟与打断插话显著改善长者体验（按住说话的请求-响应延迟长者难等）；④ 降级模式保留 HTTP/WS 按住说话，确保 WebRTC 故障不白屏，符合"可降级"产品定位。

**实现方案与技术约束**：

| 环节        | 实现方案                                                                                      |
| --------- | --------------------------------------------------------------------------------------- |
| 信令        | FastAPI 侧用 WebSocket 承载 SDP offer/answer 与 ICE candidate 交换（信令复用现有 WS 通道，无需新增独立信令服务器） |
| NAT 穿透    | 本地教学部署以 host 候选绕过为主；跨网段/容器网络部署 coturn TURN 中继（docker-compose 内置 coturn 服务）；ICE 协商失败自动降级为按住说话 |
| 服务端媒体处理   | 采用 aiortc（Python asyncio WebRTC 库）与 FastAPI 集成；服务端从音频轨读取 PCM 帧送流式 ASR、把 TTS PCM 写入音频轨下发，避免引入 mediasoup/Janus 的 C++/Node 依赖 |
| 实时 ASR 分帧 | 全双工下服务端从音频轨道持续分帧 + VAD 切段送流式 ASR：端侧 TEN-VAD（WASM）为主，服务端 webrtcvad 兜底（TEN-VAD 不可用/加载失败时回落）；降级模式仍用按住说话整段上传 |
| 回声消除（AEC） | 浏览器约束 `echoCancellation:true` + `autoGainControl`；TTS 优先经 WebRTC 音频轨下发以利用浏览器 AEC；AEC 不足时降级半双工（TTS 播放期间静音麦克风） |
| 反向外呼      | APScheduler 到点 → 服务端主动创建 PeerConnection → 向 pad 推送外呼信令 → pad 自动接听建连 → 数字人开口播报；外呼建连失败降级为 WebSocket 下发页面播报（FR-MED-06） |
| 工期        | WebRTC 链路纳入 Day 3–5 既有排期（与大纲一致），不额外挤占三级路由 / LangGraph / MCP / Langfuse 的 Day 6–10 排期 |

**降级触发条件**（任一命中即切按住说话降级模式）：WebRTC 建连超 5 秒未成功、ICE 协商失败、TURN 不可达、浏览器不支持 WebRTC、服务端 aiortc 异常。降级后页面提示"已切换为按键说话模式"，核心对话与用药 / 健康功能不受影响。

### 2.3 三级路由架构（必交）

```plain
长者语音（WebRTC 全双工主模式 / 按住说话降级，HTML 页面采集）
   → ASR
   → ① 规则层：安全敏感一票否决前置 + 高频固定意图（零延迟执行）
   → ② Laya / System One 分类器：处理规则覆盖不到的意图（本地开源模型，
        不要求微调）；置信度 ≥0.85 直接路由，<0.85 澄清一次
   → ③ 主控 Agent（System Two）：复杂对话与多工具组合请求；不得自动执行
        高风险写操作（改药单、关工单、删数据）
   → 工具 / LangGraph 子图 / MCP Tool 执行
   → TTS → HTML 页面播放 + 大字幕
```

规则优先级（同一输入命中多层时）：合法性校验 > 急症/敏感安全规则 > 进行中的用药/健康任务 > 固定意图 > 低置信澄清或 System 2 > 记忆个性化表达。低优先级不得覆盖高优先级。

| 急症/红色事件处置 | **安全规则层直接触发**（确定性 Workflow + HITL）                       | 规则层，**不等待主控 Agent 规划** |

| 戏曲点播      | 普通 Tool（本地素材）                                            | 规则层或主控 Agent           |
| 长期记忆      | Memory Tool（pgvector）                                    | 主控 Agent               |

## 3. 用户与场景

### 3.1 角色与权限矩阵

| 角色  | 核心诉求        | 可执行                                                          | 不可执行                |
| --- | ----------- | ------------------------------------------------------------ | ------------------- |
| 长者  | 容易说、看得清、能求助 | 语音对话、天气、戏曲、用药确认、健康采集、**一键求助（SOS 按钮）**、查看/纠正/删除本人记忆           | 查看他人数据、修改药单、关闭工单    |

### 3.2 身份识别（长者 ID + 声纹双条件，必交）

**统一身份模型（无论几人间）**：每次语音交互的说话人身份由两个条件共同判定——

1. **长者 ID（设备绑定 1v1 圈定）**：模拟设备与长者 1:1 绑定，声纹候选集=绑定长者本人（恒 1 位）；双人间另一位长者使用其自己的设备，各自 1v1。本设备只认绑定长者的声纹；他人在本设备前的语音即使与库中其他长者的声纹高度相似，也不会被误认为本人。
2. **声纹匹配（判定具体是谁）**：注册时由**使用者本人现场录制 3 段**语音（页面引导，知情告知，可随时删除），提取声纹 embedding；每次语音交互提取说话人 embedding，与候选集内各长者声纹做 cosine 比对，≥0.55 判定为该长者（CAM++ 教师口径，2026-11-07 主理人裁决下调，原 0.85；实测同人得分 0.517–0.568，0.85 必误拒，见修订记录 v2.8）。

| 判定结果              | 处理规则                                |
| ----------------- | ----------------------------------- |
| 声纹命中某位绑定长者（≥0.55） | 进入该长者会话：加载个人记忆，健康/用药操作归属该长者         |
| 低置信度（<0.55）       | **必须主动询问确认**："请问是哪位在说话？"，由用户选择或语音回答 |
| 询问后确认成功           | 进入确认长者的会话                           |
| 仍无法确定             | 进入**通用模式**：不读取任何个人记忆、不写入健康记录、不确认用药  |
| 声纹服务不可用           | 降级为"长者 ID + 主动确认"（页面询问），不静默猜人       |

**教学级声纹能做什么 / 不能做什么**（避免验收争议）：

- ✅ 能实现"识别本人声音、拒绝他人"：固定麦克风、安静房间、配合性说话人的教学场景下，3D-Speaker CAM++（或等价开源模型）embedding + 阈值比对可稳定区分"本人 vs 他人"。
- ✅ 误判有兜底：他人相似度不足时被拒并触发主动确认；本人被误拒时也可通过主动确认继续，不会把用户锁死。
- ❌ 不能防**录音重放**（播放本人录音可骗过纯声纹比对）；❌ 不能防高仿真语音合成/变声攻击；❌ 不做跨设备、跨信道、嘈杂环境下的一致性承诺——这些属于生产级声纹认证（需活体检测、挑战应答、防重放流水号等），列为本版非目标。

> 数据模型（Day 1 冻结，按 Day1 设计方案细化）：设备与长者 **1:1** 绑定；双人间声纹候选集经 `beds` 床位表 JOIN 房间得出；`elders.session_seq` 单调递增，服务端按 `(elder_id, session_seq)` 生成会话 thread_id，防伪造（见 §4.10 三道隔离闸门 FR-ADM-06）。

声纹验收需报告：注册最短语音时长、声纹模型版本、注册样本数、测试说话人数、FAR/FRR、主动确认兜底记录。运行时原始语音默认不保存；如需短期保存调试，须独立开关 + 明确用途 + 自动删除，且不得用于训练或调优。

### 4.5 用药提醒

**药单**：**医生在后台增、改、停、查，护工与管理员仅只读**（药单属教学演示数据管理，不构成真实处方）；每次提醒保存药品剂量快照，修改生成新版本不影响历史；不接受语音改药单。P0 每种药独立提醒，合并卡片为 P1。

> 注：本权限口径与大纲 §7.2 / Day1 设计方案 §6（护工可改药单）不一致，为本版**有意决策**（见 §1.6）；Day1 设计方案药单表的 `created_by` 字段设计需相应调整。

**四次触达时间线**（以计划时间 T0 为基准，首次提醒 + 三次重试 = 共四次触达）：

| 时间 | 行为（无有效响应时） |
| --- | --- |
| T0 | 首次提醒，等待 60 秒确认 |
| T+5 分钟 | 第一次重试，等 60 秒 |
| T+10 分钟 | 第二次重试，等 60 秒 |
| T+15 分钟 | 第三次重试 + **终态分流**，生成风险事件和工单 |

每次触达独立记录：attempt_no、发送时间、页面回执（card_rendered/tts_finished）、TTS 结果、长者响应与渠道。"提醒送达"以 HTML 页面回执为准；TTS 失败但卡片渲染成功记为已送达并追加 `tts_failed`。

**终态分流**：

| 分支 | 终态 | 规则 |
| --- | --- | --- |
| 已服自报 | `taken_reported` | 记录自述/时间/渠道，停止重试；**不代表实际服药** |
| 拒服 | `refused` | 立即停止重试，生成风险事件+护工跟进工单 |
| 伴不适 | 转敏感检测 | 命中急症规则直接红色事件 |
| 有回执、无响应 | `missed_unconfirmed` | 至少一次获得页面回执但四次均无有效响应；**不得写成实际漏服** |
| 四次均无回执 | `notification_failed` | **不得表述为长者拒服或已知悉未确认** |
| 补确认 | 追加 `late_taken_reported` | 不覆盖原终态；关联工单保持待处理，**不自动关闭** |
| 页面离线/断网 | 不影响服务端调度 | 服务端照常计时并记录无回执；重连显示错过摘要，不集中补播 |

### 4.6 健康采集（5 个问题 5 个字段）

每日 19:00 启动（19:00–20:00 窗口，20:00 强制结束；工作人员可补启动）。采集支持两种渠道：**长者语音问话**（主渠道）与**护工代填表格**（FR-HLT-06，用于长者不便语音作答、听力/表达障碍或设备异常时），两条渠道写入同一套 5 字段并走同一分级引擎。**来源字段统一为单字段 `source`**（与 Day1 方案对齐，二维 channel×trigger 折叠为枚举）：`voice_scheduled` 语音定时采集 / `voice_active` 语音主动主诉 / `staff_scheduled` 护工定时代填 / `staff_active` 护工主动代填；代填数据 source 含 `staff_*` 并记录操作者与时间，日报中标注来源。**5 个问题对应 5 个结构化字段**：

| 问题 | 字段 |
| --- | --- |
| 今天测量的收缩压是多少？ | `systolic` |
| 今天测量的舒张压是多少？ | `diastolic` |
| 昨晚睡了几个小时？ | `sleep_hours` |
| 今天心情怎么样？ | `mood_score`（1–5 分整数评分，1=很差 5=很好，与大纲/Day1 方案对齐）+ 可选 `mood_note` 自由描述 |
| 今天身体有什么不舒服？ | `complaint`（无/文本） |

**演示分级规则**（教学演示，非临床诊断；多项并存取最高等级）：

| 等级 | 规则 | 系统行为 |
| --- | --- | --- |
| 红 | 收缩压 ≥180 **或** 舒张压 ≥120；或命中急症症状规则 | 立即通知护工 + 红色事件 + 工单，人工复核并行；**任一分量达标即判红，另一分量缺失不阻断** |
| 黄 | 收缩压 140–179；舒张压 90–119；收缩压 <90；舒张压 <60；睡眠 <5h；mood_score ≤2 且未命中急症；非急症主诉；任一采集项缺失 | 黄色人工复核任务 |
| 绿 | 收缩压 90–139 且舒张压 60–89，其他无异常 | 仅保存记录 |

数据校验：非数字、负值、睡眠 >24h 无效；两分量均有时校验收缩压 > 舒张压；无效项重问一次，再失败标缺失继续。无红分量但血压任一分量缺失判黄。极端数值照常分级并标"数值待复核"。每次分级保存 `rule_version`。

### 4.7 告警与工单

**通知对象与升级**：红色事件 → 负责护工 + **同时通知监护人**（家属知情权，走 Mock 家属通知渠道，避免机构独自担责），**2 分钟无人确认升级管理员**（不重复建单，升级计时从事件生成开始，不因通知失败暂停）；黄色事件 → 护工或医生，当班内完成（班次 08:00–20:00 / 20:00–次日08:00，换班不改截止时间）。
