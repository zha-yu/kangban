## 0. 范围与读者

本文冻结**照护台 console 五个 Mock 页**对应的 REST 接口口径：请求/响应字段、权限边界、错误码。每个字段行标注 TD §3 表与字段出处——**无凭空字段**；前端 Mock 层（`frontend/src/console/*-api.ts`）交付真实接口时仅替换内部实现、保持导出签名（各文件头既有约定）。

## 1. 通用约定（与既有已交付接口同口径）

| 项 | 口径 | 出处 |
| --- | --- | --- |
| 鉴权 | 工牌 JWT（staff 体系），`Authorization: Bearer`；console 三角色（护工/医生/管理员）按 §2 分权 | 身份契约 §E；PRD §4.5 |
| 身份注入 | 操作人/范围一律服务端从 token 解出注入（`runtime_context`），**前端不传 elder_id 之外的越权参数**；护工只看负责长者（AC-18） | AGENTS §4 红线 9 |
| 错误体 | `{detail, code, trace_id}`；业务冲突 409 `CONFLICT`、参数 422 `VALIDATION_ERROR`、越权 403 `FORBIDDEN` | day03/contracts.md C3 |
| 时间 | 请求/响应一律 ISO 8601 UTC；展示层转 Asia/Shanghai | AGENTS §8 |
| 写操作留痕 | 状态流转写 `work_order_transitions`；敏感操作另记 `audit_logs`（TD §3） | FR-ALT-02 |

## 3. 端点契约

### 3.1 工单看板（WorkOrdersPage ← workorders-api.ts）

#### W-1 `GET /api/work-orders`

- 权限：登录员工全量可见（看板即交接清单，FR-ALT-01）；无 elder 范围过滤（看板需全局处置）。
- 响应 `200 { items: WorkOrder[] }`，`WorkOrder` 一次返回含 `transitions`（完整状态历史，FR-ALT-02；Mock 同签名）：

| 字段 | 类型/可空 | 出处 |
| --- | --- | --- |
| order_id | uuid | TD work_orders.order_id |
| order_no | text（`WO-YYYYMMDD-NNNN`） | TD work_orders.order_no（§3.1 例外②） |
| elder_id | uuid | TD work_orders.elder_id |
| elder_name | text | **JOIN 展示字段**（elders.name，Mock 冗余同口径） |
| room_label | text | **JOIN 展示字段**（rooms+beds 拼文案，Mock 同口径） |
| type | 枚举 8 值：missed_medication/sensitive_alert/health_alert/device_fault/sos/collection_missed/drug_question/follow_up | TD work_orders.type（裁决 C2/D2） |
| severity | red/yellow（**建单快照，不随后同步**） | TD work_orders.severity |
| status | new/acknowledged/in_progress/resolved/closed/reopened | TD work_orders.status（PRD §4.7） |
| escalated | bool | **推导字段**：来源事件 2 分钟无人确认（risk_events.acknowledged_at IS NULL ∧ created_at+2min ≤ now，FR-ALT-01）；前端不再自行推算（开放问题 Q-2） |
| assignee_id / assignee_name | uuid / text，可空 | TD work_orders.assignee_id + JOIN staff_accounts.name |
| false_alarm / false_alarm_reason | bool / text 可空 | TD work_orders.false_alarm / false_alarm_reason |
| actual_handled_at | timestamptz 可空（红档 resolve 必填） | TD work_orders.actual_handled_at |
| note | text 可空 | TD work_orders.note |
| created_at / closed_at | timestamptz 否/是 | TD work_orders.created_at / closed_at |
| transitions[].transition_id / order_id / from_status / to_status / actor_id / at / note | 见左 | TD work_order_transitions 同名列（actor_id 系统流转可空） |
| transitions[].actor_name | text 可空 | **JOIN 展示字段**（staff_accounts.name） |

#### W-2 `POST /api/work-orders/{order_id}/transitions`

- 请求 `{ action: acknowledge|start|resolve|close|false_alarm|reopen, note?, actual_handled_at? }`。
- 状态机与校验 = PRD §4.7 + Mock 既有实现逐条对齐：acknowledge（new/reopened→acknowledged，自动占用 assignee=操作人）；start（仅 acknowledged）；resolve（仅 in_progress；**红档 actual_handled_at 与 note 必填**）；close（仅 resolved，note 必填）；false_alarm（未关闭态，note 必填，置 false_alarm 并保留原始输入）；reopen（仅 closed，**仅管理员**，note 必填）。
- 响应 `200 WorkOrder`（W-1 同构）；非法流转 409 `CONFLICT`、缺必填 422 `VALIDATION_ERROR`、越权重开 403 `FORBIDDEN`。
- 每次成功流转写一条 `work_order_transitions`（TD §3；system 流转 actor_id 为空）。

### 3.2 通知中心（AlertsPage ← alerts-api.ts）

#### N-1 `GET /api/notifications`

- 权限：按 token 身份过滤 `target_id`（护工看 target_type=staff 自己；家属端另有接口不在本文）。
- 响应 `200 { items: NotificationItem[] }`：

| 字段 | 类型/可空 | 出处 |
| --- | --- | --- |
| notification_id | uuid | TD notifications.notification_id |
| target_type / target_id | text / uuid | TD notifications.target_type / target_id |
| type | text（emergency_health/sensitive/missed_medication/report_ready/sos…开放枚举） | TD notifications.type |
| payload | `{title, summary, order_no?, room_label?}`（jsonb 脱敏后展示） | TD notifications.payload + 本契约冻结形状（D-8） |
| channel | inapp/webpush（P0 只落库+演示卡片，裁决 B5） | TD notifications.channel |
| status | generated/pending/delivered/acknowledged/failed | TD notifications.status（AC-23 状态机） |
| is_mock | bool | TD notifications.is_mock |
| retry_count | int | TD notifications.retry_count |
| dedupe_key | text 可空 | TD notifications.dedupe_key（部分唯一，AC-25） |
| created_at / sent_at | timestamptz 否/是 | TD notifications.created_at / sent_at |
| acknowledged_by | uuid 可空 | TD notifications.acknowledged_by |
| acknowledged_by_name | text 可空 | **JOIN 展示字段** |
| acknowledged_at / read_at | timestamptz 可空 | TD notifications.acknowledged_at / read_at |

#### N-2 `POST /api/notifications/{notification_id}/read` → 已读（只写 read_at，**已读≠确认**，AC-23）
#### N-3 `POST /api/notifications/{notification_id}/acknowledge` → 人工确认（仅 status=delivered 可确认，禁止跳步；写 acknowledged_by/at 并 status→acknowledged；非法跳步 409 `CONFLICT`）

### 3.3 健康代填（HealthFormPage ← health-api.ts）

#### H-1 `GET /api/elders?status=active`（**复用已交付 E7**，不做新端点）——负责长者候选，服务端范围过滤即 AC-32。

#### H-2 `POST /api/health-records`

- 权限：护工/医生/管理员；`elder_id` 不在负责范围 → 403。
- 请求：

| 字段 | 类型/可空 | 出处 |
| --- | --- | --- |
| elder_id | uuid | TD health_records.elder_id |
| source | `staff_scheduled`（定时代填）/ `staff_active`（主动代填） | TD health_records.source（四值枚举取护工两值，裁决 B1；AC-32 不采用 staff_report） |
| systolic / diastolic | int 可空（0–300 CHECK） | TD health_records.systolic / diastolic（单分量达红即红，AC-21） |
| sleep_hours | numeric(3,1) 可空（0–24） | TD health_records.sleep_hours |
| mood_score / mood_note | int 可空（1–5）/ text 可空 | TD health_records.mood_score / mood_note |
| complaint | text 可空 | TD health_records.complaint（主诉原文） |

- 响应 `200`：`record_id`（uuid）、`severity`（green/yellow/red，**服务端规则引擎写入**，前端不传）、`rule_version`、`recorded_at`、`follow_up`（**响应层提示文案，非表列**——红→紧急工单+通知；黄→人工复核任务；绿→入库日报，PRD §4.6）。
- 补录为**追加新行不覆盖**（AC-22）；operator_id 服务端注入（source 含 staff_* 时必填，AC-32）。

### 3.4 药单（MedicationPage 只读 / MedicationEditPage 医生维护 ← medication-api.ts）

#### M-1 `GET /api/elders/{elder_id}/medication-plans`

- 权限：登录员工；护工越权写走 M-2 兜底。
- 响应 `200 { items: MedicationPlan[] }`：

| 字段 | 类型/可空 | 出处 |
| --- | --- | --- |
| plan_id | uuid | TD medication_plans.plan_id |
| elder_id | uuid | TD medication_plans.elder_id |
| drug_name / dose | text | TD medication_plans.drug_name / dose（教学演示数据） |
| schedule_cron | text（前端仅支持「每天 HH:MM」最小转换） | TD medication_plans.schedule_cron |
| start_date / end_date | date 否/是 | TD medication_plans.start_date / end_date |
| version | int（修改 version+1，历史提醒保留旧快照 AC-27） | TD medication_plans.version |
| created_by | uuid | TD medication_plans.created_by（仅医生） |
| created_by_name | text | **JOIN 展示字段**（staff_accounts.name；Mock 直接给文案同口径） |
| status | active/stopped | TD medication_plans.status |

#### M-2 医生写操作（护工/管理员 403+审计，PRD §4.5）

- `POST /api/elders/{elder_id}/medication-plans`：新增（version=1、active、created_by=token 医生）；请求体 = `{drug_name, dose, schedule_cron, start_date, end_date?}`。
- `PATCH /api/medication-plans/{plan_id}`：修改（version+1；stopped 不可改 → 409）。
- `POST /api/medication-plans/{plan_id}/stop`：停用（status→stopped；**无删除语义**）。
- 必填校验：drug_name/dose/schedule_cron/start_date（422）。

### 3.5 复核队列（ReviewQueuePage ← review-api.ts）

#### R-1 `GET /api/health-records/pending-reviews`

- 队列 = `review_status=pending` 的黄/红档；**红档置顶、recorded_at 倒序**（排序服务端做，Mock 前端排序仅演示期口径）。
- 权限：黄档复核护工/管理员可操作，红档仅医生（§2）。
- 响应字段 = TD health_records 全列 + JOIN 展示字段：

| 字段 | 类型/可空 | 出处 |
| --- | --- | --- |
| record_id / elder_id / recorded_at / source / operator_id | — | TD health_records 同名列（operator_id source 含 staff_* 时非空） |
| operator_name / elder_name / room_no / bed_no | text | **JOIN 展示字段**（staff_accounts / elders / rooms / beds；Mock 冗余同口径） |
| systolic / diastolic / sleep_hours / mood_score / mood_note / complaint | 可空 | TD health_records 同名列 |
| severity / rule_version / version | 否 | TD health_records.severity / rule_version / version |
| review_status | pending/confirmed/corrected | TD health_records.review_status |
| reviewed_by / reviewed_at | uuid 可空 / timestamptz 可空 | TD health_records.reviewed_by / reviewed_at |
| reviewed_by_name | text 可空 | **JOIN 展示字段** |
| superseded_by | uuid 可空 | TD health_records.superseded_by（原值保留可查，AC-22） |
| superseded_reason | `review_correction`/`backfill` 可空 | **TD 无此列**（D-1/Q-1：服务端按版本链推导） |
| review_note | text 可空 | **TD 无此列**（Q-1：Mock f7 D4 自裁字段） |

#### R-2 `GET /api/health-records/{record_id}` / `GET /api/health-records/{record_id}/chain`

- chain = 同 elder_id + 同 recorded_at 的版本链，version 升序（Mock getRecordChain 同口径）。

#### R-3 `POST /api/health-records/{record_id}/confirm`：确认无误（仅 pending；写 reviewed_by/at；请求体 `{note?}`）。
#### R-4 `POST /api/health-records/{record_id}/correct`：纠错（仅 pending）——生成**新行**（record_id 新、version+1、severity 按规则引擎重算、review_status=confirmed、reviewed_by=操作人），原行置 `corrected` 且 `superseded_by` 指向新行（AC-22 原值保留）；请求体 `{fields: {systolic?...complaint?}, review_note?}`；至少改一项（422）。
