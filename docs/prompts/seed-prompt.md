# 种子提示词（Seed Prompt）

> 大纲课时 1.4 的指定交付物：现场一起写本项目的种子提示词。
> 后续所有「让 AI 生成一个模块」的请求都从本文件派生，不要每次从零即兴描述。
> 相关：`docs/工作流选型说明.md`（形态判据）、`AGENTS.md`（禁区与高风险文件清单）。

---

## 1. 六要素（缺一不可）

| 要素 | 本项目怎么写 | 缺失的后果 |
| --- | --- | --- |
| **Context 上下文** | 康伴 = CCRC 长者卧室的 3D 数字人陪伴系统；本模块在分层中的位置（api / services / agents / graphs / audio） | AI 按通用健身房/客服系统想象，产出跑偏 |
| **Task 任务** | 一句话说清「只做这一个模块」，附要改的文件路径 | 范围蔓延成「顺手把认证也写了」 |
| **Constraints 约束** | 技术栈版本、分层硬约束（services 唯一写库）、禁区 12 条、必须复用的既有模块 | 重复造轮子、越过 services 直接写库 |
| **Expected Result 验收** | 可执行命令 + 期望输出（`curl` 200 / `pytest -q` 通过 / 表字段清单） | 无法判断是否完成，只能"A 看起来不错" |
| **形态：Workflow 还是 Agent** | 从 `docs/工作流选型说明.md` 四问法得出，明确写出「直线」或「状态图」 | 把直线流程画成图，或把有状态流程写成 if |
| **停止条件** | 「跑通 XXX 就停，不要自行扩展」+ 卡住时的汇报格式 | 无限重写、越改越大 |

## 2. 模板

```text
【Context】
项目：康伴（SilverMate），CCRC 长者卧室的 3D 数字人陪伴系统。
本模块位置：app/<层>/<文件>，属于 <层职责一句话>。
依赖的既有模块：<列出，不许重写>。

【Task】
只做一件事：<一句话>。
允许改动的文件：<路径清单，其他文件一律不许动>。

【Constraints】
- 技术栈：FastAPI + Pydantic v2 + SQLAlchemy 2.x(async) + PostgreSQL 15/pgvector（按 pyproject.toml 已声明版本，不新增依赖）
- 分层：services 是唯一写库层；api 只校验+调 services；模块间不横向 import
- 禁区：不硬编码密钥；不连生产库；模型不得自报 elder_id；不改已合入的 Alembic 迁移
- 复用：<已有的工具/服务/常量，避免重复实现>

【形态】
<直线 / 状态图>，理由：<四问法的哪几问为是>。

【Expected Result】
1. <命令> → <期望输出>
2. <命令> → <期望输出>
3. 人工检查点：<要读 diff 的地方>

【停止条件】
跑通上面全部验收即停止。不要顺手扩展功能、不要重命名无关文件。
若卡住：先汇报「卡在哪一步、依据是什么、建议两个方案」，等我选。
```

## 3. 实例 A：生成一个 service（1.4 之后的常规动作）

```text
【Context】康伴，services 层，负责 health_records 的写入与分级判定。
【Task】只实现 app/services/health.py 的 save_record(elder_id, fields) 与其单测。
【Constraints】技术栈同 pyproject；写库只能在这里；severity 阈值必须来自常量而非 prompt；
               fake 数据不得含真实身份信息；不新增依赖。
【形态】直线。
【Expected Result】pytest tests/test_services_health.py -q → 5 passed；
                   grep 阈值常量 → 只出现在 app/core/config.py 与 services/health.py。
【停止条件】测试全绿即停；不要顺手写 API 路由。
```

## 4. 实例 B：让 AI 先出方案（高风险文件必须先方案）

```text
【Task】我要改 auth 体系（高风险清单内文件）。
【要求】先只输出方案，不要写代码：
  1. 涉及哪些文件、各自的 diff 要点；
  2. token 生命周期（Access 2h / Refresh 7d / 设备会话 24h）如何保证；
  3. token_version 失效逻辑放在哪一层；
  4. 三套凭证（人/设备/工牌）如何避免串用；
  5. 你打算新增的测试用例清单。
【停止条件】我批准后你才写代码；未批准前不要创建或修改任何文件。
```

## 5. 反例对照

| 坏提示词 | 为什么坏 | 改法 |
| --- | --- | --- |
| 「帮我加个登录」 | 无上下文、无范围、无验收、无形态 | 用模板，列出改动文件与 `pytest` 期望 |
| 「按最佳实践实现健康模块」 | "最佳实践"不可验收 | 引用 PRD 的具体条款号与字段清单 |
| 「把整个后端写出来」 | 一次做十个模块，错误会叠加 | 拆成一个模块一次，每次跑验收 |
| 「随便用个日志库」 | 违反禁区 12（不擅自引入框架） | 明确指定标准库 logging |

## 6. 提示缓存注意（成本）

固定前缀 = system 指令 + 人设 + 工具定义，**必须保持稳定**；每轮变化的内容（长者原话、
检索记忆、时间）只放在前缀之后。前缀一改，整段 cache 失效（大纲 2.1 的 90% token 省法是靠这个）。
