# 康伴前端页面方案（配色冻结版）

> **状态**：配色已确认（2026-11-05）。主体 **A″ 月白青瓷 · 低饱和**；信号色 **徽标淡底（100 级）+ 深字（700 级）**。
> 本文件是三端页面开发的唯一视觉约定。改色值必须同时改 `frontend/src/theme/tokens.css` 与此处表格，不允许在组件里写死十六进制。
> 依据：`docs/康伴3D数字人_PRD.md`、`frontend/src/pad/` 现有实现。

---

## 0. 冻结结论

| 约束 | 决定 |
| --- | --- |
| 主题 | 全端共用一套浅色（A″），**无深色块、无深色模式、无自动反色**；顶栏/侧栏/卡片与背景同族 |
| 主色 | `#527A72` 灰青瓷，白字按钮对比 ≈4.8:1；只有一个主色承担交互 |
| 彩度 | 大面积低饱和（S≈20%），靠明度差 + 1px 线 + 留白分层，不靠色相分层 |
| 信号色 | 标准语义色相不原创；**700 级深字 + 100 级淡底徽标**，仅小面积出现 |
| 字体 / 字阶 | 沿用现有 PingFang SC 系统栈与 60px 大字幕字阶，不动 |
| PRD 行为口径 | "红色事件 / 黄色复核 / 正常"作为业务字段值不变；红档置顶（FR-ALT-02）、2 分钟升级（FR-ALT-01）、SOS 常显 ≥48px（FR-ALT-06）全部不动 |

**一句话边界**：大面积只有中性灰白与灰青瓷；有彩度的信号只出现在徽标、状态点、图表异常点上；深色只留给正文。

## 1. 设计 token

唯一真源：`frontend/src/theme/tokens.css`（Tailwind v4 `@theme static`）。`static` 保证 25 个变量全部输出到 `:root`，console / family 的 MUI 主题可直接读取；utility 仍按需生成。

| Token | 色值 | 用途 |

| `brand-strong` | `#436A62` | 按下 / hover |
| `brand-soft` | `#EDF2F0` | 主色 8% 底：列表选中态、3D 舞台底 |

| `surface-sunken` | `#EFEFEB` | 抬升面 / 表头 / 按下态 |
| `line` | `#E2E3DE` | 1px 分隔线、描边（**不能省**） |

### 1.2 文字

| Token | 色值 | 用途 |
| --- | --- | --- |
| `ink` | `#2D302D` | 正文、大字幕终稿 |
| `ink-muted` | `#5F655F` | 次级说明、系统提示 |

| `ink-inverse` | `#FFFFFF` | 主按钮反白字 |

### 1.3 信号色配对（用户确认的形态）

| 语义 | 淡底 token / 色值 | 深字 token / 色值 | 用在哪 |
| --- | --- | --- | --- |
| 急症 / 错误 | `danger-soft` `#FEE2E2` | `danger-ink` `#B91C1C` | 红色事件、红档置顶、表单错误 |
| 待复核 / 警告 | `warning-soft` `#FEF3C7` | `warning-ink` `#B45309` | 黄色复核、用药超时、重试提示 |
| 正常 / 成功 | `success-soft` `#DCFCE7` | `success-ink` `#15803D` | 健康绿档、已服用、工单已解决 |
| 进行中 / 信息 | `info-soft` `#DBEAFE` | `info-ink` `#1D4ED8` | 正在听、连接中、信息提示 |
| 断开 / 离线 | `neutral-soft` `#F3F4F6` | `neutral-ink` `#4B5563` | 已断开、降级、禁用（**红色不占**） |

- 深字在 `canvas` 上对比度 4.6–6.8:1：小色点更清楚，视觉冲击反而比 600 级低。
- 不再往 800 级沉：会接近正文 `#2D302D`，小圆点糊成灰点，红绿蓝分不出。
- 淡底**只负责安静**，不承载识别；识别靠深字 + 文字标签 + 状态点。

### 1.4 形状

`--radius-card: 1rem`（三端统一 `rounded-2xl` / `rounded-card`）。

## 2. 使用规则（硬约束）

1. **大面积只用中性面 + 主色**。层级靠明度差、1px `line`、留白；不靠深色压边，不靠色相区分模块。
2. **信号色唯一载体是 `StatusBadge`**（`src/pad/components/StatusBadge.tsx`，console/family 后续复用同一约定）。每个状态必须同时给出：状态点 + 文字标签 + 颜色，颜色是第三线索——老年人红绿、蓝黄辨别力都下降。
3. **不铺面、不做按钮底、不上 60px 大字幕**。工单列表用左侧细条 + 徽标，不整行染色；表单错误用深红文字说明 + 徽标，不用红边框。
4. **状态条映射**（本批已落地）：正在听 → `info`，正在想 → `warning`，正在说 → `success`，连接中 → `info`，已断开 → `neutral`。**红色不进状态条**。
5. **SOS 是操作不是状态**：实心 `brand` + 大字"一键求助"，不用红色小块，避免与"红色事件"混淆（FR-ALT-06）。
6. **断开 / 降级一律 `neutral`**，红色只留给急症、红色事件、表单错误。
7. **console 14 天趋势图**（FR-HLT-09）用明度阶梯 + 线型 / 点标记区分序列，红黄绿只标异常点；红档置顶靠排序 + 徽标，不靠整页配色。
8. **3D 舞台 / 静态头像**：`brand-soft` 圆底 + `brand-line` 细描边。浅底上 3D 模型轮廓靠描边与柔阴影，不靠深背景；VRM 形象选素色，它可以是全页唯一有彩度的主角。

## 4. 组件规范

### 4.1 字阶与触控

| 端 | 主标题 / 大字幕 | 正文 | 次级 | 硬性下限 |
| --- | --- | --- | --- | --- |
| pad | 60px bold（大字幕） | 24–30px | 20–24px | 正文 ≥20px（FR-UI-02） |
| console | 20–24px | 14–16px | 12–14px | 表格行高 ≥40px |
| family | 20–24px | ≥16px | 14–16px | 375px 无横向滚动 |

触控：pad 实际 ≥64×64px，console/family ≥48×48px（PRD FR-UI-02 门槛）。圆角统一 1rem。

### 4.2 组件约定

| 组件 | 约定 |
| --- | --- |
| 主按钮 | `bg-brand` + `text-ink-inverse`，按下 `bg-brand-strong`；尺寸靠现有超大 padding，不靠颜色加"可点感" |
| 次按钮 | `bg-surface` + 1px `border-line` + `text-ink`，按下 `bg-surface-sunken` |
| 危险操作 | **不铺红底**；`text-danger-ink` 文字 + 描边 + 二次确认 |
| 禁用 | `opacity-50` + `neutral-ink`，不使用信号色 |
| 卡片 | `bg-surface` + 1px `border-line` + `rounded-2xl`，无重阴影；卡片间靠留白与线分区 |
| 状态徽标 | `StatusBadge` 五档 tone，状态点 + 文字 + 颜色三线索；`size` sm/md/lg 对应 console/pad 不同密度 |
| 表单 | `bg-surface` + `border-line`，focus 用 `brand` ring；错误用 `danger-ink` 文字 + 徽标，不靠红框 |
| 表格 / 看板 | 红档置顶靠排序 + `danger` 徽标 + 左侧细条；不整行染色，不用多色相区分列 |
| 3D 舞台 | 圆形 `brand-soft` 底 + `brand-line` 描边；加载失败切静态 `<img>` 沿用同一处理（FR-3D-02） |
| 无障碍 | 状态变化 `aria-live="polite"`；徽标 `role="status"`；不单靠颜色传达等级；纯白仅用于反白字，不用作大面积底 |

### 4.3 对比度自检

`brand` 上反白字 ≈4.8:1；`ink` 在 `canvas` 上远超 4.5:1；五档深字在 `canvas` 上 4.6–6.8:1；100 级淡底与深字配对本身不构成对比要求（文字始终是深字）。

## 5. 工程落地

```
frontend/src/
  theme/tokens.css      ← 唯一真源（本批已建，@theme static）
  pad/index.css         ← @import "tailwindcss"; @import "../theme/tokens.css";
  pad/components/StatusBadge.tsx
  console/              ← 占位，后续批次建入口
  family/               ← 占位，后续批次建入口
```

- 新增入口时同样两行 import 即可拿到完整变量与 utility；`vite.config.ts` 的 `rollupOptions.input` 再补 `console` / `family`。
- **MUI 主题注意点**：`palette.primary.main` 若写 `var(...)`，MUI 的颜色运算（`lighten` / `darken`）无法解析。必须显式给全四档，避免运行时报错：

```ts
palette: {
  primary: {
    main: "var(--color-brand)",
    dark: "var(--color-brand-strong)",
    light: "var(--color-brand-soft)",
    contrastText: "var(--color-ink-inverse)",
  },
  background: { default: "var(--color-canvas)", paper: "var(--color-surface)" },
  text: { primary: "var(--color-ink)", secondary: "var(--color-ink-muted)" },
},
shape: { borderRadius: 16 },
```

- **不做什么**：不引深色模式、不引第三套主题、不引衬线/装饰字体、不改现有字阶、不让 pad 的 three-vrm 进其他入口、不用信号色做按钮底。
