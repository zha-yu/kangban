## 0. 冻结结论

| 约束       | 决定                                                                                        |
| -------- | ----------------------------------------------------------------------------------------- |
| 主题       | 全端共用一套浅色（P2 藤紫），**无深色块、无深色模式、无自动反色**；顶栏/侧栏/卡片与背景同族                                        |
| 主色       | `#6B5B7B` 藤紫，白字按钮对比 ≈6.2:1；只有一个主色承担交互                                                     |
| 彩度       | 大面积低饱和（S≈13–18%），靠明度差 + 1px 线 + 留白分层，不靠色相分层                                               |
| 信号色      | 标准语义色相不原创；**700 级深字 + 100 级淡底徽标**，仅小面积出现                                                  |
| 字体 / 字阶  | 沿用 PingFang SC 系统栈；大字幕 v1.8 起分场景：常态引导 60px / 对话当前句 48px / 任务与 SOS 提示 30px；右栏对话记录正文 24px，均 ≥20px 下限（FR-UI-02） |
| PRD 行为口径 | "红色事件 / 黄色复核 / 正常"作为业务字段值不变；红档置顶（FR-ALT-02）、2 分钟升级（FR-ALT-01）、SOS 常显 ≥48px（FR-ALT-06）全部不动 |

**一句话边界**：大面积只有中性微紫与藤紫；有彩度的信号只出现在徽标、状态点、图表异常点上；深色只留给正文。

### 1.3 信号色配对（用户冻结的形态）

| 语义       | 淡底 token / 色值            | 深字 token / 色值           | 用在哪                          |
| -------- | ------------------------ | ----------------------- | ---------------------------- |
| 急症 / 错误  | `danger-soft` `#FEE2E2`  | `danger-ink` `#B91C1C`  | 红色事件、红档置顶、表单错误、SOS 结果徽标      |
| 待复核 / 警告 | `warning-soft` `#FEF3C7` | `warning-ink` `#B45309` | 黄色复核、用药超时、重试提示、重问一次          |
| 正常 / 成功  | `success-soft` `#DCFCE7` | `success-ink` `#15803D` | 健康绿档、已服用、已送达、工单已解决           |
| 进行中 / 信息 | `info-soft` `#DBEAFE`    | `info-ink` `#1D4ED8`    | 正在听、连接中、需要确认、信息提示            |
| 断开 / 离线  | `neutral-soft` `#F3F4F6` | `neutral-ink` `#4B5563` | 已断开、降级、禁用、未采集、布局预览（**红色不占**） |

- 深字在 `canvas` 上对比度 4.6–6.8:1：小色点更清楚，视觉冲击反而比 600 级低。
- 不再往 800 级沉：会接近正文 `#2D302D`，小圆点糊成灰点，红绿蓝分不出。
- 淡底**只负责安静**，不承载识别；识别靠深字 + 文字标签 + 状态点。

### 1.4 形状（嵌套递减）

| token | 值 | 用在哪 |
| --- | --- | --- |
| `--radius-card` | `1rem` / 16px | 卡片、面板、弹窗、空态容器（三端统一 `rounded-2xl`） |
| `--radius-control` | `10px` | 按钮、输入框、下拉、卡内子块、提示条 |

同圆角不等于协调：外层卡片与内部控件取同一半径，边角会"糊"在一起；外层 16px、内层 10px 才是同心圆角关系。pad 长者端仍以 `rounded-2xl` 为主，控件 token 主要服务 console / family 的原生 CSS。

## 2. 使用规则（硬约束）

1. **大面积只用中性面 + 主色**。层级靠明度差、1px `line`、留白；不靠深色压边，不靠色相区分模块。
2. **信号色唯一载体是** **`StatusBadge`**（`src/pad/components/StatusBadge.tsx`，console/family 后续复用同一约定）。每个状态必须同时给出：状态点 + 文字标签 + 颜色，颜色是第三线索——老年人红绿、蓝黄辨别力都下降。
3. **不铺面、不做按钮底、不上 60px 大字幕**。工单列表用左侧细条 + 徽标，不整行染色；表单错误用深红文字说明 + 徽标，不用红边框。
4. **状态条映射**：正在听 → `info`，正在想 → `warning`，正在说 → `success`，连接中 → `info`，已断开 → `neutral`。**红色不进状态条**。
5. **SOS 是操作不是状态**：实心 `brand` + 大字"一键求助"，不用红色小块，避免与"红色事件"混淆（FR-ALT-06）。结果页的 `danger` 徽标是事件状态，与按钮区分开。
6. **断开 / 降级一律** **`neutral`**，红色只留给急症、红色事件、表单错误。
7. **console 14 天趋势图**（FR-HLT-09）用明度阶梯 + 线型 / 点标记区分序列，红黄绿只标异常点；红档置顶靠排序 + 徽标，不整页配色。
8. **3D 舞台 / 静态头像**：`brand-soft` 圆底 + `brand-line` 细描边。浅底上 3D 模型轮廓靠描边与柔阴影，不靠深背景；VRM 形象选素色，它可以是全页唯一有彩度的主角。
9. **紫色色相冲突对策**：紫（≈270°）与 `info` 蓝（220°）相邻，短波紫/蓝在老年晶状体黄化下最先衰减。所以主色只承担交互、**不铺面**；状态条固定顶栏、主按钮在底部，靠位置与文字标签分离，不靠颜色区分；不为解决冲突去改已冻结的徽标色值。

**高度预算（1920×1080，v1.7 起 DEV 与生产一致，v1.8 沿用）**：顶栏 112 + 字幕 152 + 操作区 232 = 496px；`main` 584px。常态舞台 518px（余量 66px）；任务两栏态与对话记录两栏态都是舞台 300px、右栏 `h-full` 560px（正文区滚动）——两栏态由 `main` 的 `pt-6`（24px）在顶部留白，内容盒因此为 560px，卡片不再贴住页面顶栏，四段高度与字幕坐标不变。字幕区的 40px 增量换来固定溢出裁切，任务态 footer 高度不变所以字幕位置仍不跳。**结论：舞台完整落在 `main` 内**，且 DEV 不再比生产少 61px；`main` 另有 `overflow-hidden` 兜底更小视口；右栏宽度 `min(960px, 60vw)`，在 1280px 视口下 300 + 64 间距 + 768 面板 + 96 左右留白 = 1228px，不横向溢出。

**按钮层级**：唯一主色实心按钮「呼叫小伴」（`px-20 py-6 text-4xl`）；降级「按住说话」与设置「换个形象」并排一行，走描边浅底 `compact` 形态（≥56px 高）。不再三个按钮等宽堆叠。standby 下 `HoldToTalk` / 声纹提示下发的文本优先于唤醒引导语显示，避免降级话术被吞掉。

**形象选择角色卡**：结构参考离线形象总览「3:4 透明底全身立绘 + 底部信息区」，14 张立绘落地 `public/assets/avatars/{id}.png`（420×560，Q2 裁决的截图替换在此完成）。卡片 / 相框 / 文字保持低饱和浅底，彩度只留在立绘里；选中态 = `border-brand` + 右上角「使用中」徽标；非选中卡静态显示「点一下换上 →」（触屏无 hover，可点性必须常显）；`lipsync=none` 用单行中性徽标「不支持口型」，不换行、不做禁用块。一触即选口径不变，图片缺失回落渐变占位。开发模式 `?picker=1` 可直达选择页验收（仅 `import.meta.env.DEV` 生效，不进真实演示链路）。

### 3.6 任务下发契约（v1.5 定案，前端侧）

**PRD 已经定了传输，但主路径当前是断的**：§2.2 / FR-UI-10 / FR-MED-06 把「反向 WebRTC 外呼」定为主动触达主路径，外呼建连失败降级为「WebSocket 下发页面播报」；§4.6 的健康采集由 19:00 定时或护工补启动；FR-VPR-02 的身份确认由声纹低置信触发。而当前 `RealtimeClient` 只在点呼叫 / 唤醒词命中时建连，**没有自动接听外呼的能力**——主路径要实现就得动语音链路，不属于本批范围。

**定案**：前端不绑定传输，只消费一条与来源无关的「任务命令」；实际下发**优先走 FR-MED-06 已允许的 WS 降级帧**（复用已有 `/ws/signal` 连接、设备身份、重连与鉴权，不新开通道、不加常驻轮询）。等反向外呼落地后，把外呼信令翻译成同一条命令即可，主屏不用改。

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 通道 | 复用 C2 信令 WS 新增任务下行帧（**建议，待后端冻结**） | 已有连接与设备鉴权；REST 轮询有延迟且常驻页面白耗请求，只适合做离线补单兜底；独立 WS 要多维护一条连接 |
| 前端入口 | `task-channel.ts` 的 `emitPadTask` / `subscribePadTasks`（`window` 事件总线 `kangban:pad-task`） | 适配器与主屏解耦：`App.tsx` 只订阅命令，不知道是外呼、WS 帧还是调度器 |
| 幂等 | `taskId` 为键，同键重复 `open` 不重启面板 | 对齐 FR-MED-04 触达键口径；`close` 只对 `taskId` 匹配的当前任务生效 |
| 字幕 | 任务提示走 `notice`（中性 UI 反馈），真实 ASR/TTS 到达即让位 | 原型期没有 TTS，不能把 UI 文字伪装成数字人语音（FR-UI-02） |
| 回程 | `card_rendered` / `tts_finished` 回执 | `MedicationCard.onRendered` 已留幂等回调；**本批不伪造请求**，PRD 的「提醒送达」以页面回执为准 |

**命令形状**（`frontend/src/pad/task-channel.ts`）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `taskId` | `string` | 幂等键；建议后端用 `reminder_id + attempt_no` / 采集记录 id / 声纹会话 id |
| `kind` | `"medication" \| "health" \| "identity"` | 面板类型；SOS 是常显按钮，不是下行任务 |
| `source` | `outbound_call \| ws_fallback \| scheduler \| staff \| voiceprint \| dev` | 仅展示与排查用，不改变面板行为 |
| `hint` | `string` | 长者可读的界面提示，进大字幕 notice 区 |
| `payload` | 三类载荷之一 | 用药快照 `MedicationSnapshot`；采集 `{startedAt, source}`；身份 `{candidates, reason}`。载荷缺失回落教学模拟数据，前端不猜业务事实 |
| `issuedAt` | `number?` | 到达时间，供后续去重 / 过期丢弃 |

`close` 事件形如 `{ type:"close", taskId, reason: "completed" | "timeout" | "user_exit" | "superseded" }`。

**三条待接适配器（均尚未实现，不许假装已接）**：

1. **C2 信令 WS 任务帧**（首选）→ `SignalSocket` 收到后 `emitPadTask(open)`。⚠️ `frontend/src/pad/protocol.ts` 的 `parseServerSignal` 会**静默丢弃未知 type**，且其文件头规定「契约改动必须先改团队 `contracts.md` 并同步此处」。所以新增 `ServerSignal` 变体必须先走团队契约冻结流程，**本批没有改 `protocol.ts`**。
2. **REST 轮询 `GET /api/pad/tasks`**（离线补单兜底）→ 拉到新任务 emit。后端当前只有 `GET /api/pad/avatar-config`，没有任何任务端点。
3. **反向外呼 `auth_ok` 携带 task 扩展** → 与 1 同属 C2 契约，等自动接听落地后合并。

**当前唯一真实来源**：开发态演示入口 `DemoSwitcher`（`source="dev"`）与 `?demo=` 直达，两者都调 `makeDevTask()` 造同形命令再 emit，因此这个入口本身就是契约的可运行样例。**生产构建里没有任何任务来源**，浮层不出现；面板底部标注「任务经总线以开发命令下发 · 后端契约待接 · 数据为教学模拟」。

  family/                       ← 登录链路已落地（task-05），业务页后续批次

- 新增入口时同样两行 import 即可拿到完整变量与 utility；`vite.config.ts` 的 `rollupOptions.input` 三入口（`index.html` / `console.html` / `family.html`）已全部挂上，构建验证见 task-05 卡（`pnpm --dir frontend build` 全绿）。
- **console/family 样式注意点**：组件样式为原生 CSS（各入口 `index.css`），一律 `var()` 引用 token，禁止硬编码十六进制色值。入口 `index.css` 必须保持首行 `@import "tailwindcss"` 再 `@import "../theme/tokens.css"`——`@theme` 块必须经 Tailwind 处理才会输出为真实 `:root` 变量，浏览器会整体忽略未处理的 `@theme` 块（此为 2026-11-06 联调白屏的根因之一）。注意组件的 CSS 类在两个入口各自定义，不共享模块文件（卡 §0：console/family 独立同构，禁止互相 import）。
- **不引入组件库**：console/family 不使用 MUI 等第三方 UI 组件库。原因（2026-11-06 主理人裁决）：MUI v9 的颜色运算（`augmentColor` 的 `lighten`/`darken`、组件 hover 的 `alpha`）实测不支持 CSS 变量字符串，palette 传 `var(...)` 会运行时抛 `MUI: Unsupported color` 白屏；而喂真实色值又需要绕开 token 唯一真源。登录链路已按纯 React + 原生 CSS 落地（form/input/button + 语义化 aria 属性），后续 console/family 页面沿用此形态。

- **不做什么**：不引深色模式、不引第三套主题、不引衬线/装饰字体、不改现有字阶、不让 pad 的 three-vrm 进其他入口、不用信号色做按钮底、不在前端做健康分级。
