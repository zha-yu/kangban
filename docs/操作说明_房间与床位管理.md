# 操作说明 · 房间与床位管理

> 状态：`已冻结（v1.0，2026-11-09）`　｜　适用角色：管理员（admin）
> 上游依据：`docs/康伴3D数字人_PRD.md` FR-ADM-11（验收）｜`docs/接口契约_房间与床位管理.md` v1.0（接口口径）
> 入口：照护台（console）→ 左侧导航「房间与床位」

---

## 1. 谁可以用

| 角色 | 可见菜单 | 可执行操作 |
| --- | --- | --- |
| 管理员 admin | 「房间与床位」可见 | 全部（查询 / 新建 / 编辑 / 删除 / 批量） |
| 护工 care_worker | 不可见 | 无（直接调接口返回 403） |
| 医生 doctor | 不可见 | 无（403） |
| 家属 guardian | 不可见（应走家属端） | 无（403） |
| 设备会话 device | 不可见 | 无（403） |

> 前端隐藏入口只是体验优化；真正的权限门禁在服务端。任何非 admin 主体调用管理端点一律 `403 ROLE_FORBIDDEN`，且不落任何数据。

---

## 2. 页面结构

1. **筛选区**：房号、床位号（模糊匹配）、房间状态、床位状态；「查询」应用条件，「重置」清空条件。
2. **房间区**：房号 / 状态 / 床位数 / 占用数 / 操作（编辑、删除）；每页 10 间，支持上一页/下一页。
3. **床位区**：复选框 / 房号 / 床号 / 状态 / 入住长者 / 操作（编辑、删除）；每页 10 张。
4. **批量条**：勾选床位后出现，显示已选数量，提供「设为空闲 / 维修 / 停用」与「批量删空床」。
5. **反馈**：成功为绿色提示条（`role=status`），失败为红色提示条（`role=alert`），均不显示 `trace_id` 或内部错误细节。

## 3. 房间操作

### 3.1 新建房间

在「房间」区输入房号（必填，≤64 字符，自动去首尾空格）→ 点「新建房间」。
成功：房间出现在列表，状态「空闲」，床位数 0。失败：房号已存在 → 「房号已存在」；全空白 → 无法提交。

### 3.2 编辑房号

点目标房间「编辑」→ 修改房号 → 保存。值未变化时前端直接关闭弹窗，不调用接口。
**房间状态不能在编辑弹窗里改**——它由该房间全部床位聚合派生。

### 3.3 删除房间

点目标房间「删除」→ 确认弹窗 → 「确认删除」。
- 房间下仍有床位：拒绝，提示「该房间下还有床位或设备，请先处理后再删除」。
- 房间仍被模拟设备引用：同样拒绝，需先解绑/删除设备。
- 删除成功：204，房间从列表消失；操作写入审计。

## 4. 床位操作

### 4.1 新建床位

在「床位」区选择所属房间 → 输入床号（必填，≤32 字符）→ 「新建床位」。
同一房间内床号不可重复；**不同房间允许同名床号**。房间不存在或已被删除 → 报错，请刷新后重试。

### 4.2 编辑床位

点床位「编辑」可改床号与状态：
- 状态只能选 **空闲 / 维修 / 停用**；「占用」不可手工设置——它由长者入住关系派生。
- 已入住（占用）的床位：状态下拉禁用，只能改床号；试图改状态会被服务端拒绝（409）。

### 4.3 删除床位

只能删**空床**（无入住长者且非占用）。占用床删除会被拒绝（409），请先在长者/入住流程里解除绑定。

### 4.4 批量操作

1. 勾选若干床位（可跨房间，单次 ≤100 张）；
2. 点「设为 空闲 / 维修 / 停用」或「批量删空床」；
3. 确认后一次性生效。

**原子性**：批量里只要有一张床不存在或已入住，整批都不执行，页面提示失败原因；不会出现「改了一半」。

## 5. 状态规则（务必理解）

| 床位状态 | 含义 | 谁可以写 |
| --- | --- | --- |
| 空闲 available | 可入住 | 管理员手工 / 退住自动 |
| 占用 occupied | 有长者入住 | **只能由入住关系派生**，管理员不可手写 |
| 维修 maintenance | 维修中，不可安排入住 | 管理员手工 |
| 停用 disabled | 停用，不再使用 | 管理员手工 |

房间状态自动聚合（不可手改）：

| 房间状态 | 判定 |
| --- | --- |
| 空闲 available | 无床，或全部床位空闲 |
| 部分占用 partial | 有占用床，或存在维修/停用床但未全占/全停 |
| 满员 full | 全部床位占用 |
| 维护中 maintenance | 全部床位为维修/停用 |

> 床位增删改、长者入床/换床后，房间状态都会自动重算，无需手工维护。

## 6. 筛选与分页

- 房号/床位号为**模糊匹配**，输入片段即可（如 `A-3`、`1 号`）。
- 房间状态、床位状态为精确过滤，下拉选择。
- 每页固定 10 条；总数超过一页时「下一页」可用。
- 切换筛选后自动回到第 1 页。

---

## 7. 审计与追溯

所有成功写操作都会在 `audit_logs` 留痕：操作人（员工 ID）、时间、动作（`room_create` 等 8 种）、对象 ID、变更前后快照（房号/床号/状态/入住长者 ID）。
批量操作只记一条，`detail.bed_ids` 记录本批床位，before/after 为数组。
**审计不记录长者姓名等个人信息**；审计与业务同事务，业务回滚则审计一起回滚。

## 8. 常见错误与处置

| 页面提示 | 原因 | 处置 |
| --- | --- | --- |
| 当前账号无权执行房间/床位管理操作 | 非 admin 角色 | 换管理员账号或联系管理员 |
| 房号已存在 | 全局房号重复 | 换房号 |
| 同一房间下床号已存在 | 同房床号重复 | 换床号 |
| 该房间下还有床位或设备，请先处理后再删除 | 删除前置校验未过 | 先删床位 / 解绑设备 |
| 床位已有入住长者，不能删除 | 占用床 | 先走退住/解绑流程 |
| 数据校验失败 | 空值、非法枚举、超长、显式 null | 按表单提示修正 |
| 网络异常，请稍后重试 | 后端不可达 | 检查服务与网络后重试 |

> 页面不会展示 `trace_id` 与后端内部细节；排查问题时请在浏览器网络面板或后端日志中按时间定位。
