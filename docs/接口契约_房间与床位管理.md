## 2. 房间端点

### 2.1 E20 `GET /api/admin/rooms`

| 参数 | 类型 | 约束 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `page` | int | ≥1 | 1 | 页码 |
| `page_size` | int | 1–100 | 20 | 每页条数 |
| `room_no` | str | ≤64 | — | 房号模糊匹配（`ilike`，转义 `%` `_` `\`） |
| `status` | enum | `available/partial/full/maintenance` | — | 房间状态精确过滤 |

响应 200：

```json
{
  "items": [
    {
      "room_id": "uuid",
      "room_no": "A-301",
      "status": "partial",
      "beds": [
        {"bed_id": "uuid", "bed_no": "1 号床", "status": "occupied", "elder_id": "uuid"},
        {"bed_id": "uuid", "bed_no": "2 号床", "status": "available", "elder_id": null}
      ]
    }
  ],
  "total": 1, "page": 1, "page_size": 20
}
```

> 响应**没有** `bed_count` / `occupied_count` 字段；前端由 `beds[]` 派生计数（自裁 D5）。

### 2.2 E21 `POST /api/admin/rooms`

请求 `{"room_no": "A-303"}`（`extra="forbid"`；`min_length=1`，`max_length=64`；服务层 `strip()` 后为空 → 422）。
响应 201：`{"room_id": "uuid", "room_no": "A-303", "status": "available"}`。
房号全局重复 → 409（`uq_rooms_room_no` + 服务层预查双保险）。

### 2.3 E22 `PATCH /api/admin/rooms/{room_id}`

请求仅 `{"room_no": "A-304"}`。响应 200 同 E21。
房间不存在 → 404；撞已有房号 → 409 且原值不变。房间状态不可手改，只能由床位聚合。

### 2.4 E23 `DELETE /api/admin/rooms/{room_id}`

成功 204 无响应体。房间有床位 → 409（detail 含「床位」）；仅被 `devices` 引用 → 409（detail 含「设备」）；不存在 → 404。

## 3. 床位端点

### 3.1 E24 `GET /api/admin/beds`

| 参数 | 类型 | 约束 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `page` | int | ≥1 | 1 | 页码 |
| `page_size` | int | 1–100 | 20 | 每页条数 |
| `room_id` | uuid | — | — | 按房间过滤 |
| `bed_no` | str | ≤32 | — | 床号模糊匹配 |
| `status` | enum | `available/occupied/maintenance/disabled` | — | 床位状态精确过滤 |

响应 200：

```json
{
  "items": [{
    "bed_id": "uuid", "room_id": "uuid", "room_no": "A-301",
    "bed_no": "1 号床", "status": "occupied", "elder_id": "uuid"
  }],
  "total": 1, "page": 1, "page_size": 20
}
```

> `elder_name` 后端不返回；前端降级展示 `elder_id` 前 8 位（自裁 D5）。排序固定 `(room_no, bed_no)`。

### 3.2 E25 `POST /api/admin/beds`

请求 `{"room_id": "uuid", "bed_no": "1 号床"}`（`extra="forbid"`）。响应 201 同 E24 item。
房间不存在 → 404；同房床号重复 → 409（跨房同名允许）；床号空白 → 422。

### 3.3 E26 `PATCH /api/admin/beds/{bed_id}`

请求两字段均可省，但**显式 `null` → 422**：

```json
{"bed_no": "2 号床", "status": "maintenance"}
```

- `status` 只接受 `available | maintenance | disabled`；传 `occupied` → 422（占用只能由入住关系派生）。
- `elder_id` 非空的床位改任何状态 → 409；**可以**改床号。
- 响应 200 同 E24 item。

### 3.4 E27 `DELETE /api/admin/beds/{bed_id}`

成功 204。要求 `elder_id IS NULL` 且 `status != 'occupied'`，否则 409。

### 3.5 E28 `POST /api/admin/beds/batch-status`

请求 `{"bed_ids": ["uuid", ...], "status": "maintenance"}`；`bed_ids` 1–100 条，自动去重；`status` 同 E26 约束。
响应 `{"affected": 3}`。任一 id 不存在 → 404 且整批不动；含占用床 → 409 且整批不动。批量只写一条审计 `bed_batch_status`。

### 3.6 E29 `POST /api/admin/beds/batch-delete`

请求 `{"bed_ids": ["uuid", ...]}`（1–100 条）。响应 `{"affected": 3}`。含占用床 → 409 整批不动；审计 `bed_batch_delete`（`after=[]`）。

## 4. 错误码

| HTTP | `code` | 触发场景 | detail 示例 |
| --- | --- | --- | --- |
| 403 | `ROLE_FORBIDDEN` | 非 admin 的任何主体（care_worker / doctor / guardian / device） | — |
| 404 | `NOT_FOUND` | 房间/床位不存在；批量含不存在 id | 「房间不存在：{uuid}」 |
| 409 | `CONFLICT` | 房号重复；同房床号重复；删除有床位/设备的房间；占用床改状态或删除；批量含占用 | 「房号已存在：A-301」「房间下仍有 2 张床位，请先删除床位后再删除房间」 |
| 422 | `VALIDATION_ERROR` | 空值/全空白、非法枚举、显式 `null`、显式 `occupied`、`page_size>100`、`bed_ids` 空或 >100、夹带未知字段 | Pydantic 默认或服务层中文文案 |
| 401 | — | 无凭证/凭证失效（鉴权中间件，非本路由） | — |

## 5. 权限矩阵

| 主体 | 结果 |
| --- | --- |
| `admin` | 200 / 201 / 204 |
| `care_worker` | 403 `ROLE_FORBIDDEN` |
| `doctor` | 403 `ROLE_FORBIDDEN` |
| `guardian` | 403 `ROLE_FORBIDDEN` |
| `device` | 403 `ROLE_FORBIDDEN` |

> 判定内核用 `check_roles(identity, ("admin",))`，**不用** `require_roles("admin")` 工厂：后者经 `current_staff` 会把 guardian/device 判成 401，与「四类非 admin 一律 403」冲突（自裁 D4）。

## 6. 业务规则与不变量

1. **房间状态只读**：`rooms.status` 由全部床位状态聚合：无床 → `available`；全 `maintenance`/`disabled` → `maintenance`；全 `occupied` → `full`；存在 `occupied` 或存在非 `available` → `partial`；其余 → `available`。
2. **`occupied` 不可手工写**：只能由 `beds.elder_id` 派生；PATCH 传 `occupied` → 422。
3. **占用床不可降级/删除**：`elder_id` 非空 → 改状态 409、删除 409。
4. **唯一性**：房号全局唯一；床号 `(room_id, bed_no)` 唯一；服务层预查 + DB 约束双保险。
5. **必填非空**：Pydantic `min_length=1` + 服务层 `strip()`，全空白 422 不落库。
6. **批量原子性**：`FOR UPDATE` 取全 → 去重 → 逐条校验 → 全通过才 `flush`；任一失败整批不动。
7. **审计同事务**：每次成功写操作写一条 `audit_logs`（批量一条，`detail.bed_ids` + before/after 数组）；审计写失败整笔回滚。
8. **审计边界**：`detail` 只含 `before`/`after`/`trace_id`/`bed_ids`；快照字段仅 `room_no`/`bed_no`/`status`/`elder_id`，**不含长者姓名等 PII**。
9. **审计动作名**：`room_create` / `room_update` / `room_delete` / `bed_create` / `bed_update` / `bed_delete` / `bed_batch_status` / `bed_batch_delete`。
10. **E19 语义不变**：`assign_bed` 只新增「同步受影响房间聚合状态」副作用，请求/响应/冲突码不变，与管理端共用 `aggregate_room_status`。

## 7. 与 E18 的边界

`GET /api/rooms`（E18）是接口契约 v1.8 冻结基线，本功能**不改**其实现与响应；前端「模拟设备」页继续用 E18，房间/床位管理页用 E20。二者共享 `rooms`/`beds` 表，但读路径独立。
