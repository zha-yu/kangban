## 2. 实施计划

依赖链：**T0 → T1 → T2 → (T3 ∥ T4) → T5 → T6 → T7 → T8**。关键路径约 10.5 小时。T0 是一次性装配改造，做完之后 T5 不再需要等 main.py 的空档（见 §6 N1）。

### T0 · 路由装配改为注册表（约 0.5h，一次性，解决排队）

**为什么做**：`app/main.py:83-89` 现在是 7 条手写 `include_router`，A2（装配行）、A4（校验 handler）、本计划（2 行 `include_router`）三方会挤在同一代码块 → git 三方合并必然冲突。改成注册表后，新增路由只改 `app/api/__init__.py`，各方追加到不同行，git 可自动合并，**从此不再排队**。

**怎么做**

1. `app/api/__init__.py`（当前只有一行 docstring，无人占用）新增：

```python
from fastapi import APIRouter

from app.api import audio, auth, devices, elders, health, pad

# 路由注册表：新增模块只在这里追加一行，不再改 app/main.py。
# 每项为 (router, prefix)；prefix 为空串表示路由自带完整前缀。
ROUTERS: tuple[tuple[APIRouter, str], ...] = (
    (health.router, ""),
    (auth.router, "/api"),          # auth 路由内部不带 /api，由装配层补
    (elders.router, ""),
    (devices.router, ""),
    (audio.router, ""),             # 自带 /api/audio
    (pad.router, ""),               # 自带 /api/pad
)
```

2. `app/main.py`：删掉 6 条 `from app.api import ...`，改为 `from app.api import ROUTERS`；把 83-88 行的 6 条 `include_router` 换成：

```python
for _router, _prefix in ROUTERS:
    application.include_router(_router, prefix=_prefix)
```

3. **`signaling.router` 与 `install_signaling_handler()` 保留在原位、不进注册表**：`signaling` 属 `app.audio` 域，若让 `app/api/__init__.py` 去 import，会把 `api → audio` 的依赖方向倒过来（AGENTS §2 单向依赖）。

**验收（必须逐条过）**

```bash
# ① 路由集合零变化：改造前后各导出一份 path 列表并 diff
uv run python -c "from app.main import app; print('\n'.join(sorted(r.path for r in app.routes)))" > /tmp/after.txt
# 与改造前同一命令的输出 diff，必须完全一致（含 /health、/api/auth/*、/api/elders/*、/api/devices/*、/api/audio/*、/api/pad/*、/ws/signal）
# ② import 与装配不报错
uv run python -c "import app.main; print('import ok')"
# ③ 全量不回归
uv run pytest -q          # 期望 429 passed, 1 skipped
uv run ruff check app tests && uv run ruff format --check app tests
```

**回退**：单独一个提交（`refactor(api): 路由装配改为注册表`），出问题 `git revert` 即可，不牵连任何功能改动。

**边界**：本步**只改装配方式**，不改任何路由自身的前缀、路径、依赖与响应；`app/api/*.py` 六个模块内部一行不动。

### T1 · A1 建号 CLI（约 2h）

- 新建 `scripts/create_account.py`：`--role {admin,care_worker,doctor,guardian}`、`--name`、`--phone`、`--password`；幂等（同 phone 已存在 → 打印既有 id 并 exit 0；`--strict` 时 exit 2）。
- 复用 `app.core.security.hash_password()`；直连 `get_session()`；不经过 HTTP。
- 脚本模板照 `scripts/seed_personas.py` 的 `sys.path` 修复写法（`_REPO_ROOT = Path(__file__).resolve().parents[1]` + `sys.path.insert(0, ...)` + `# ruff: noqa: E402`）。
- 验收：连续执行两次，第二次不再插入；建出的 admin 可 `POST /api/sessions` 登录。

### T2 · schema + service（约 3h）

- `app/api/schemas/staff.py`：`StaffCreateRequest(name, role, phone, password, elder_ids=[])`、`StaffUpdateRequest(role?, status?)`、`StaffResponse(staff_id, name, role, phone_masked, status)`；密码 `min_length=8`（S-01）；phone 正则 `^1\d{10}$`。
- `app/services/staff_service.py`：
  - `create_staff(...)`：查重（同时查 `staff_accounts` 与 `guardian_accounts`，避免跨表同号，对应 `auth_service.py:188` 的碰撞检查）→ `hash_password` → 插入 → 按 `elder_ids` 写 `elder_staff_assignments`。
  - `update_staff(...)`：改 `role`/`status` 时 `token_version += 1`（契约 O10）。
  - `create_guardian(...)`（G1）、`bind_guardian(...)`（E13）：数 `elder_guardians WHERE elder_id AND status='active'`，≥2 抛 `GuardianLimitExceeded`，已存在抛 `GuardianAlreadyBound`。

## 3. 完工标准（必须逐条可执行验证）

### 3.1 功能

```bash
# ① 造首个管理员（仓库里此前没有任何 admin）
uv run python scripts/create_account.py --role admin --name 李管理 \
  --phone 13700000000 --password Admin@2026
# 期望：输出 staff_id；重复执行 → "已存在 staff_id=..." 且不新增行

# ② 该账号能登录且 role=admin

  -H 'content-type: application/json' \
  -d '{"phone":"13700000000","password":"Admin@2026"}'
# 期望：200，access_token 非空

# ③ admin 建员工
curl -s -X POST localhost:8000/api/staff -H "authorization: Bearer $ADMIN" \
  -H 'content-type: application/json' \
  -d '{"name":"王医生","role":"doctor","phone":"13700000001","password":"Doctor@2026"}'
# 期望：201；重复调用 → 409 PHONE_EXISTS

# ④ 非 admin 调用 → 403
curl -s -o /dev/null -w '%{http_code}' -X POST localhost:8000/api/staff \
  -H "authorization: Bearer $CARE_WORKER" ...
# 期望：403

# ⑤ 家属建号 + 绑定
curl -s -X POST localhost:8000/api/guardians ... → 201 {guardian_id}
curl -s -X POST localhost:8000/api/elders/$ELDER/guardians \
  -d '{"guardian_id":"$G","relation":"女"}' → 201
# 第三次绑定同一位长者 → 409 GUARDIAN_LIMIT_EXCEEDED
```

### 3.2 安全

- 改 `role` 或 `status` 后，**旧 access token 立刻 401**（`token_version+1` 生效）。
- 账号 `disabled` 后登录返回 401（走 `auth_service.py:208` 的既有分支），改回 `active` 可登录。
- 响应体与日志**不出现** `password_hash` 明文或完整手机号（脱敏沿用 `_mask_phone`）。
- 密码 <8 位 → 422，且错误信息不回显密码。
