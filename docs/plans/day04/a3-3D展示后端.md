## 2. 四个必须先定死的口径

### S-01（自裁）`version` 用「内容指纹」，不是自增序号

C7 写「persona.avatar_url 变更即递增」，但 `personas` 表没有 version 列，而迁移文件属 A1 写域、本卡禁触。

**做法**：`version = zlib.crc32(f"{avatar_url}|{fallback_image_url}|{rotation_y_offset}|{avatar_cache_version_salt}".encode()) & 0x7FFFFFFF`。

（末位 `avatar_cache_version_salt` 是兜底开关：哪天需要强制全端失效、又不想动资产时，改这个值即可。）

- 语义保住了：**配置一变，version 必变**，前端缓存失效成立；
- 丢失的只是「单调递增」，前端只用它做「和上次不同就重取」，不依赖有序；
- 记入 C7 变更记录（须 A1/A2/前端三方idle时通告，属契约文字细化，不改字段）。

### S-02（自裁）`rotation_y_offset` 只来自 Settings

`personas` 无朝向字段，取值链第三档才是前端内置，所以第二档只能是配置常量：

`avatar_rotation_y_offset: float = 0.0`（当前资产是 VRM 1.0，不需要补偿）。

VRM0 的 180° 由前端 `rotateVRM0` 处理，**后端不下发 π**——否则 VRM1 会被多转一次。

### S-04（自裁）`deploy/` 目录不在技术设计文档 §2.1 的目录约定里

技术文档 §2.1 列了 `app/`、`frontend/`、`mcp-servers/`、`alembic/`、`eval/`、`tests/`、`spikes/`、`docs/`，**没有 `deploy/`**。但 day-04 分工与本卡写作用域都要求 `deploy/assets/`、`deploy/nginx*.conf`，且 A1 的声纹容器也约定放 `deploy/voiceprint/`。

**做法**：沿用团队已形成的 `deploy/` 约定，本卡只占两个路径：

```
deploy/
├── assets/avatars/        # 本卡：.vrm（git 忽略）+ fallback png（可入库）
├── nginx.conf             # 本卡：/avatars/ 段
└── voiceprint/            # A1：不碰
```

不新建 `deploy/README` 抢占目录说明权；目录说明写在根 README 的资产小节里。Day 10 做 7 服务 compose 时再统一收编。

### A-01（已裁决：不进 compose）nginx 现在不存在，compose 什么时候进

两个文档说法冲突：day-04 计划 M16 要求「改 `docker-compose.yml` + nginx 配置」；而 `docker-compose.yml:2` 注释与大纲都把 nginx 排在 Day 10，且 compose 属 AGENTS §5 高风险文件。

### A-02（已裁决：允许新建 `app/services/persona_service.py`）
