## 1. 事实口径（只引 PRD 与技术文档）

- **状态机**（PRD §4.7）：`new → acknowledged → in_progress → resolved → closed`；关闭必填处置结果；红色事件必填实际处置时间；误报可关但必填原因并保留原始输入；管理员可重开并保留原因。
- **看板规则**（FR-ALT-02）：按严重度排序、红档置顶；未处理列表（new/acknowledged/in_progress）即天然交接清单；任一工单可查完整状态变更历史。
- **升级**（FR-ALT-01 / AC-12）：红色事件 2 分钟无人确认 → 原事件标 `escalated`，不建第二个事件/工单；计时从事件生成开始。
- **字段**（技术文档 §3.4）：`order_no`、`elder_id`、`type`（missed_medication/sensitive_alert/health_alert/device_fault/sos/collection_missed/drug_question/follow_up）、`severity`（建单快照，红/黄，不随后同步）、`status`（含 reopened）、`assignee_id`、`false_alarm` + `false_alarm_reason`、`actual_handled_at`（红色必填）、`note`、`created_at`/`closed_at`；历史表 `work_order_transitions`：`from_status`/`to_status`/`actor_id`/`at`/`note`。
- **样式**：原生 CSS，全部 `var()` 引用 `src/theme/tokens.css`；红/黄/进行中/成功信号色用 `--color-danger-*` / `--color-warning-*` / `--color-info-*` / `--color-success-*` 徽标淡底 + 深字（§1 冻结口径：信号色只做徽标，不做按钮底、不铺面）。

## 3. 步骤（S1–S4）

### S1 · Mock 层 `workorders-api.ts`
- 类型：`WorkOrderType` / `WorkOrderStatus` / `Severity` / `WorkOrder` / `WorkOrderTransition` / `TransitionAction`。
- Action 与状态机：`acknowledge`（new→acknowledged）、`start`（acknowledged→in_progress）、`resolve`（in_progress→resolved；红档强制 `actual_handled_at` + `note`）、`close`（resolved→closed；`note` 必填）、`falseAlarm`（未关闭→closed，`false_alarm=true` + 原因必填）、`reopen`（closed→reopened，D3 仅管理员，原因必填）。
- 内存数据 8 条：红档未确认（倒计时展示）、红档已 escalated、红档处理中、黄档各 type、误报关闭（保留原始输入）、resolved 待关闭；`transitions` 随单预置。
- 全部函数 `async` + 模拟延迟（150–400ms），返回新数组引用；切换真实接口时只改本文件。

### S2 · 侧栏骨架 `AppLayout.tsx`
- 按角色渲染菜单项：护工 5 项（工单看板可用 active，负责长者 / 健康代填 / 药单只读 / 告警通知中心置灰）；医生 / 管理员各 4 项全置灰。
- 顶栏：左侧「康伴 · 照护台」，右侧当前用户 + 角色 + 退出按钮（复用 api.ts `logout`）。
- 触控元素 ≥48px。

### S3 · 看板页 `WorkOrdersPage.tsx`
- 排序：severity 红置顶 → 状态未处理在前 → `created_at` 倒序；筛选条：状态 / 类型 / 红黄 / 「未处理」视图。
- 列表行：`order_no`、类型、长者、severity 徽标、status 徽标、escalated 徽标（红档未确认超 2 分钟）、升级倒计时（红档未确认未满 2 分钟）、`created_at`、当前处理人。
- 操作区按状态机渲染（D3：重开仅管理员）；resolve / close / falseAlarm / reopen 弹出表单（备注 / 处置时间 / 误报原因必填校验，danger-soft/ink 配对，不回显 trace_id）。
- 详情展开：建单快照字段 + transitions 完整历史（操作人 / 时间 / from→to / 备注）。

### S4 · 装配与验证
- App.tsx 分流接线；`pnpm --dir frontend build` 通过；grep 确认 zero 硬编码 hex；浏览器手验三角色分流与状态机流转。
