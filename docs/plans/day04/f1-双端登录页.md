## 1. 目标与边界（与任务卡一致，不扩不缩）

- **做**：两个相互独立的登录模块（console 员工端 / family 家属端），各自含登录页 + 登录后占位首页（角色显示 + 退出按钮）；MPA 双入口装配 + 共用 MUI 主题；登录态持久化与 access 过期自动 refresh。
- **不做**：登录后的业务页（工单看板、日报等，第 3/4 批）；权限矩阵前端拦截（后端已做）；前端单测框架（卡 §5.4 明确不新增）；任何 `app/**` 后端改动；两模块互相 import 或 import `src/pad/**`。
- **执行约束**：纯前端；发现后端 bug 报 a0 卡；发现基线文档问题报告不自行改。

### S4 · 登录态与刷新封装（= 任务卡 F3，前置：S2）

**工作内容**：将 S2/S3 的最小版 `api.ts` 各自补全为完整 fetch 封装（**两模块各自独立实现一份，允许重复**）：

1. **存储**：localStorage key 用入口前缀命名——console：`kb_console_access_token` / `kb_console_refresh_token` / `kb_console_profile`；family：`kb_family_*` 同构。
2. **`login(phone, password)`**：`POST /api/sessions`，成功存三把 key 并返回 `principal`；401/网络错按统一文案抛给页面。
3. **`fetchCurrent()`**：`GET /api/sessions/current`（Bearer），用于刷新页面后恢复登录态与角色。
4. **401 统一处理 + 自动续期**：任何带鉴权请求收到 `code=TOKEN_EXPIRED`（或 401 且本地有 refresh_token）→ 用 `POST /api/sessions/refresh` 换新 access → **重放原请求一次**；refresh 也 401/失败 → 清本入口全部 key → 回登录页。防并发刷新：同一时刻只允许一个 refresh 在途（模块内单例 Promise），其余 401 等待其结果。
5. **`logout()`**：清 key + 回登录页（占位首页退出按钮复用）。

**交付物**：`src/console/api.ts`、`src/family/api.ts`（完整版）。

**自检标准**：
- [ ] 登录后刷新页面不掉登录态，角色正常显示；
- [ ] DevTools 手动把 `access_token` 改成非法串 → 下一次请求自动触发 refresh → 重放成功（Network 可见 `/api/sessions/refresh` + 原请求二次发出）；
- [ ] 手动清掉/污染 refresh_token → 自动回登录页；
- [ ] 两端 key 前缀互不冲突：console 登录后 family 仍显示未登录（反之亦然）。

## 3. 与后端契约对照表（实现唯一依据，摘自 app/api/auth.py 实测）

| 端点 | 方法 | 请求 | 200 响应 | 失败 |
| --- | --- | --- | --- | --- |
| `/api/sessions` | POST | `{phone, password}` | `{access_token, refresh_token, token_type:"bearer", expires_in:7200, principal:{kind,id,role,name}}` | 401 `{detail, code, trace_id}`；422 校验错 |
| `/api/sessions/refresh` | POST | `{refresh_token}` | `{access_token, expires_in}`（refresh 不轮换） | 401 同上（`TOKEN_EXPIRED` 等） |
| `/api/sessions/current` | GET（Bearer） | — | `{kind, id, role, name, scope_elder_ids}` | 401 同上 |

**与任务卡的差异登记（执行按此表，卡上留痕）**：卡 §3 写的登录端点为 `POST /api/sessions/login`，实际代码与接口契约为 `POST /api/sessions`；按卡 §6「以 `app/api/auth.py` 为准」执行。E1 请求体 `phone` 后端仅约束非空（1–32 位），前端的 11 位/`1` 开头校验属前端体验规则，两者不冲突。
