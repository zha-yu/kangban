# A3 · WebRTC 媒体层 Day 3 执行计划

## 0. 执行摘要

### 0.1 一句话目标

在 `app/audio/webrtc.py` 内独立完成 aiortc 媒体层：经 A2 的信令 WS 完成 SDP/ICE 协商，接收浏览器 Opus 音频轨并稳定转换为 16 kHz/16 bit/单声道 PCM，向 A1 的 `ASRProvider.stream()` 提供 60 ms 帧，把 TTS PCM 写成浏览器可播放的下行音频轨，并在 `asr_start` 时立即打断旧播报、清理缓冲、阻止旧音频回灌。

### 0.2 本计划不做什么

- 不修改 `app/audio/signaling.py`、`app/main.py`、`app/api/**`、`app/core/**`、`app/services/**`、`app/models/**`、迁移、前端或任何他人写作域文件。
- 不实现 ASR/TTS Provider、业务回复、三级路由、Agent、声纹、3D 数字人、反向外呼、数据库写入。
- 不为 Day 3 新增依赖、表或迁移；`alembic head` 保持 `0003_fix_day1_ck_names`。
- 本文件是计划，不是代码实现。执行阶段 A3 的固定写作用域仍只有 `app/audio/webrtc.py`。
- 测试文件所有权存在冲突，默认由 A5 持有 `tests/`；A3 只提供用例向量与联调验收，除非 09:30 前获得书面协作授权。

### 0.3 完成定义

A3 当日完成必须同时满足：

1. 本机 localhost 浏览器 10 次建连 10 次成功；无需 coturn。
2. 浏览器说话后，服务侧日志可见连续、格式正确的 60 ms PCM 帧流，且同一帧流可派生 30 ms 帧供 A5 VAD 使用。
3. 服务侧写入的 TTS PCM 能在浏览器连续播放，时长误差不超过 1 个 20 ms 帧。
4. `asr_start` 后服务侧 20 ms 内停止旧音频写轨；旧 `turn_id` 的 TTS 数据不能再进入队列；浏览器侧从开始说话到静音不超过 200 ms。
5. ICE 失败或超时可在 `webrtc_ice_timeout_seconds + 1 s` 内关闭 PC、释放任务并向 A2 回报结构化失败原因。
6. 10 次建连—关闭循环后活跃 PC 数为 0、模块自建任务数为 0；重复关闭不抛异常。
7. 所有媒体日志携带同一 `trace_id`，不打印 token、完整 SDP、完整 ICE candidate 或原始音频。
8. A3 的 `git diff --name-only` 只出现 `app/audio/webrtc.py`，以及被明确授权的测试文件。
9. A5 所有的 `tests/test_audio_webrtc.py` 全绿；若 D1 未授权 A3 写测试，A3 仍须运行该测试、修复媒体缺陷并提交证据，不能以“测试不是我写的”作为未通过理由。

| `open_connection` | A2 → A3 | opaque `connection_id`、`trace_id`、回调集合 | 建立媒体会话占位；不创建 PC，不做鉴权 | 不读 token、不解析 WS、不写审计 |
| `handle_offer` | A2 → A3 | `connection_id`、SDP 字符串 | 创建/复用 PC，挂下行轨，设置 remote，创建 answer，通过 `on_answer` 回传 SDP | 不生成 offer、不解析 WS 帧 |
| `add_ice_candidate` | A2 → A3 | `connection_id`、C2 的 `candidate` JSON 字符串 | 解析 `candidate/sdpMid/sdpMLineIndex`；offer 前到达则缓存，offer 后按序添加 | 不负责 candidate 的 WS 序列化 |
| `begin_turn` | A2 → A3 | `connection_id` | 开新 ASR 会话，返回 `turn_id`；先补发 600 ms preRoll，再持续送新帧 | 不生成回复、不调用 TTS |
| `end_turn` | A2 → A3 | `connection_id`、`turn_id` | 结束当前 ASR 输入，flush 尾帧，等待 provider 结束；不关 PC | 不关闭媒体连接、不清理下一轮 |
| `barge_in` | A2 → A3 | `connection_id`、可选 `turn_id` | 使当前 `turn_id` 失效，清空下行队列，停止旧 TTS 写轨 | 不改业务状态、不判断用户说了什么 |
| `enqueue_tts_pcm` | A2/A1 协调层 → A3 | `connection_id`、`turn_id`、16 kHz/16 bit/mono raw PCM | 校验归属与格式，转 48 kHz/20 ms 帧入有界队列 | 不合成 TTS、不决定文本、不重试供应商 |
| `close_connection` | A2 → A3 | `connection_id`、原因 | 幂等关闭 PC、轨道、ASR 任务、定时器与缓冲 | 不关闭 WS、不写数据库 |
| `on_answer` | A3 → A2 | SDP 字符串、`connection_id` | 交给 A2 下行 `answer` | 不直接发 WS |
| `on_ice_candidate` | A3 → A2 | `candidate`、`sdpMid`、`sdpMLineIndex` | 交给 A2 按 C2 序列化为 `ice` 消息 | 不直接发 WS |
| `on_asr_event` | A3 → A2 | `turn_id`、C1 `ASREvent`、`trace_id` | 交给 A2 转成 `asr_partial`/`asr_final`/`error` | 不修改文本、不伪造 confidence |
| `on_vad_event` | A3 → A2 | `connection_id`、`VadEvent(kind, segment)` | 端侧 VAD 失效时的服务端兜底判决：`speech_start` / `speech_end`；`segment` 仅 `speech_end` 携带且只留内存 | 不发明 C2 消息、不自行开关 ASR turn、不落盘音频 |
| `on_state_changed` | A3 → A2 | 状态、原因、统计 | 供 A2 记录和触发清理 | 不控制前端 UI |
| `on_media_failed` | A3 → A2 | 结构化原因：`ice_failed`/`ice_timeout`/`track_ended`/`format_error`/`backpressure` | 供 A2 记录并向 A4 转发必要错误；A4 以自己的 5 秒计时触发降级 | 不直接切 REST、不直接控制前端、不发明 C2 未冻结错误码 |

### 3.3 音频数据契约

| 层 | 格式 | 帧长 | 字节数 | 说明 |
| --- | --- | --- | --- | --- |
| 浏览器上行 | Opus，通常 48 kHz，单/双声道 | 20 ms | 由 RTP 决定 | A4 必须开启 AEC/NS/AGC，并发送 `sendrecv` 音频 m-line |
| aiortc 解码 | PyAV `AudioFrame` | 20 ms | 由采样格式决定 | 不假设永远是 48 kHz 或单声道；按实际 `sample_rate/layout` 惰性初始化重采样器 |
| A3 规范化 | PCM16 little-endian，16 kHz，mono | 20 ms | 640 B（320 samples） | 单次重采样后作为唯一源，后续所有派生都从这一路分叉 |
| ASR 帧 | PCM16，16 kHz，mono | 60 ms | 1920 B（960 samples） | 唯一送入 `ASRProvider.stream()` 的格式 |
| 服务端 VAD 帧 | PCM16，16 kHz，mono | 30 ms | 960 B（480 samples） | 由 60 ms 帧按 2×30 ms 切分，或由同一 20 ms 流重组；不得另做一次重采样 |
| TTS 输入 | PCM16，16 kHz，mono raw | 任意 | 偶数长度 | 若为 WAV/带容器头或采样率不符，明确报 `format_error`，不猜、不裁头 |
| 下行播放 | PCM16，48 kHz，mono | 20 ms | 1920 B（960 samples） | 用 PyAV 重采样 16→48 kHz；PTS 从 0 单调递增 |
| preRoll | PCM16，16 kHz，mono | 60 ms × 10 | 600 ms | A3 内部环形缓冲；`begin_turn` 先补发，最多 10 帧 |

**禁止事项：**

- 禁止使用 `samples[::3]`、`np.repeat` 等抽点/重复采样替代重采样。
- 禁止把同一 60 ms 帧直接传给 30 ms VAD 接口。
- 禁止在 `asr_end` 丢弃不足 60 ms 的尾帧；应零填充到整帧后发出，最多增加 59 ms 静音。
- 禁止将原始音频写盘、写库或打进 trace。
- 禁止把 16 kHz PCM 当成 48 kHz 直接写轨；禁止把 WAV 头当 PCM 播放。

### 3.4 PC 生命周期状态机

```text
NEW
  → OPEN (A2 已鉴权并分配 connection_id)
  → OFFER_RECEIVED (收到首个合法 offer)
  → ANSWER_CREATED (下行轨已挂载，answer 已回调)
  → CONNECTING (ICE 开始)
  → CONNECTED (ICE/DTLS 可用，媒体可收)
  → CLOSING (WS 关闭 / ICE 失败 / 主动挂断 / 服务停止)
  → CLOSED

异常分支：
  OFFER_RECEIVED / ANSWER_CREATED / CONNECTING --5s 超时--> FAILED → CLOSED
  CONNECTED --ICE disconnected 超过 5s--> FAILED → CLOSED
  任意状态 --不可恢复格式错误/轨道结束--> FAILED → CLOSED
```

状态约束：

- 每个 `connection_id` 最多一个活跃 PC；重复 offer 默认拒绝并记录，不创建第二套 PC。
- `close_connection` 必须幂等；关闭后所有 `begin_turn`/`enqueue_tts_pcm` 返回“会话已关闭”，不抛未处理异常。
- `close_connection` 必须 `await pc.close()`，取消媒体任务并 `gather(..., return_exceptions=True)`，再从 registry 移除。
- `track_ended` 只结束媒体会话，不自动切 REST；降级由 A4 依据失败事件和自身 5 秒计时执行。

### 3.5 与其他任务的对接清单

#### 与 A1

- **A1 → A3：** C1 的 `ASRProvider.stream()`、`ASREvent`、`ASRResult` 类型；TTS 输出必须是“16 kHz/16 bit/mono 原始 PCM”，不得混入 WAV 头。
- **A3 → A1：** 以 60 ms/1920 B 帧持续喂入；不修改 `ASRResult`，不做 confidence 造假；`confidence=None` 原样进 `on_asr_event`。
- **失败边界：** A1 抛 `ASRUnavailable`/`ASRProtocolError`，A3 停止当前 turn、保留 PC、通过 `on_asr_event`/`on_media_failed` 上报；A3 不重试供应商，也不自行降级到 REST。

#### 与 A2

- **A2 → A3：** 鉴权成功后的 `connection_id`、`trace_id`、offer、ICE、`asr_start/asr_end`、WS 关闭；不得把原始 WS 对象传给 A3。
- **A3 → A2：** answer、ICE、ASR 事件、媒体状态、结构化失败原因；不得直接调用 `websocket.send_*`。
- **生命周期冲突裁决 D2：** 当前任务卡要求“WS 死 → 关 PC”，adhoc 方案要求“WS 断开时 PC 保活”，C2 要求 A2 清 ASR/TTS 缓冲、PC 由 A3 关闭。**默认执行任务卡与 C2：A2 最终关闭连接时调用 A3 立即关闭 PC；不实现第二套保活语义。** 若 09:30 裁决采用保活，则改为“A3 暂停媒体、保留 PC 30 秒，重连后恢复；30 秒未恢复再关闭”，但必须由 A2 明确通知，不能双方各自猜。

#### 与 A4

- **A4 → A3：** offer 必须包含一个 `sendrecv` 音频 transceiver，且 `getUserMedia` 开启 `echoCancellation/noiseSuppression/autoGainControl`；offer 的 SDP 由 A2 透传，不在 A3 重新生成。
- **A3 → A4：** answer 带下行音频轨；浏览器收到后可播放 TTS/回声。
- **打断双侧：** A4 检测本地 speechstart 后立即停本地播放器并清前端缓冲，同时发 `asr_start`；A2 调 A3 `barge_in`。A3 只能保证服务侧 20 ms 内停写，浏览器抖动缓冲的最终静音由 A4 负责。联合验收目标：从 speechstart 到可听静音 ≤200 ms。
- **失败：** A3 通过 `on_media_failed` 把 `ice_failed`/`ice_timeout` 交给 A2；A2 记录并按现有 C2 通道转发必要信息。A4 以自己的 5 秒建连计时和现有错误通道触发按住说话降级；A3 不直接改页面状态。

#### 与 A5

- **30 ms 帧交接（代码已接）**：A3 在收轨分帧后把 30 ms/960 B 帧逐帧喂给 A5 的 `VadSession.feed_frame()`；判决跃迁由 A3 翻译为 `VadEventKind.speech_start` / `speech_end`，经 `on_vad_event(connection_id, VadEvent)` 回调交给 A2。`VadEvent.segment` 仅在 `speech_end` 携带 A5 切出的完整语音段（含 A5 侧 600 ms preRoll），只留内存、不打印、不落盘。
- **A5 → A3：** `vad.py` 的 30 ms 服务端 VAD 判定；A3 只提供 30 ms PCM 帧和判定回调入口，不复制 VAD 算法、不改 `VadSession` 阈值。
- **消费边界：** C2 尚未冻结服务端 VAD 的客户端消息，A2 接线层当前只记录 `on_vad_event`；兜底模式下是否据此开/关 ASR turn 或触发打断，待 A2 契约补齐后由 A2 决定，A3 不越权。
- **A3 → A5：** 媒体单测向量、日志字段、10 次建连记录、ICE 失败记录、打断队列快照；测试文件默认由 A5 编写。
- **测试所有权 D1：** 若 A5 书面授权 A3 写 `tests/test_audio_webrtc.py`，A3 才可在该文件内写测试；否则 A3 只运行 A5 的测试并提交失败证据，保持“只改 webrtc.py”的边界。

### 4.7 13:10–14:10 M4：TTS PCM 下行写轨与背压

**执行步骤：**

1. **13:10–13:25 下行轨队列。** 每个连接一个 `AudioStreamTrack`；队列元素为 20 ms/960 sample/1920 B 的 48 kHz mono 帧；`recv()` 等待帧，队列空时阻塞等待，不忙轮询。
2. **13:25–13:40 PCM 校验与转换。** 校验 `len(pcm) % 2 == 0`、无 RIFF/WAV 头、采样率约定为 16 kHz；用有状态 resampler 16→48 kHz，再切 20 ms；PTS 从 0 开始，每帧 +960。
3. **13:40–13:52 有界队列与背压。** 队列上限按 15 秒音频设计；超限拒绝整段入队并发 `backpressure`，不允许无界增长或悄悄截断。Day 3 写死回复应短于上限。
4. **13:52–14:00 发送参数。** 在 answer 后尝试设置 `maxBitrate = webrtc_audio_bitrate_kbps * 1000`；设置失败只记录降级，不影响媒体。
5. **14:00–14:10 下行自检。** 用 1 秒 16 kHz PCM 验证输出 50 个 20 ms 帧、总时长 1 秒、PTS 连续、无爆音/变调（人耳 + 时长双检）。

**交付物：** 可闻 TTS 写轨、20 ms 帧队列、格式校验、背压、码率设置。

**自检：**

- 1 秒 PCM → 50 帧，总字节数 96,000 B（48 kHz×2 B×1 s），时长误差 ≤20 ms。
- 连续入队 15 秒不丢帧；超过上限被拒绝且日志有 `backpressure`，PC 不断。
- TTS 播放结束后队列为空，下一次 `enqueue_tts_pcm` 可正常开始。
- 浏览器听到的是正常语速，不是抽点/重复采样的变调。

### 4.8 14:10–14:30 M5：打断、播放代际与旧音频隔离

**执行步骤：**

1. **14:10–14:17 `turn_id` 代际。** 每次 `begin_turn` 生成新 `turn_id`；TTS 入队必须携带同一 `turn_id`。
2. **14:17–14:24 `barge_in`。** 递增播放代际、清空下行队列、标记旧 turn 失效；已在发送中的一帧允许完成，下一帧起必须静音。
3. **14:24–14:30 防回灌与幂等。** 旧 `turn_id` 的 `enqueue_tts_pcm` 直接拒绝并计数；重复 `barge_in` 不重复清空、不抛异常；ASR 新 turn 可立即开始。

**交付物：** 服务侧 20 ms 级打断、旧音频隔离、背压队列清理、状态日志。

**自检：**

| 检查 | 通过标准 |
| --- | --- |
| 队列清空 | `barge_in` 后队列长度归零 |
| 旧音频 | 旧 `turn_id` 入队 100% 拒绝，日志含 `stale_turn` |
| 残留 | 服务侧最多 1 个在途 20 ms 帧，下一帧起不再发送旧音频 |
| 端到端 | A4 本地停播 + A3 清队列，speechstart→可听静音 ≤200 ms |
| 幂等 | 连续 5 次 `barge_in` 无异常、无负队列、无任务泄漏 |
