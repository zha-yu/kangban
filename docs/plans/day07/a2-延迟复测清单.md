# A2 延迟复测清单（换环境复测用）

> 状态：待执行　｜　产出：dev-A　｜　日期：2026-11-10
> 目的：本机（IDE 常驻占满 CPU）给出不了 A2 延迟的诚实结论，本清单让**任何一台干净机器**能在
> 30 分钟内跑出可判定的数字，并把环境事实一并留证。

## 0.0 复测前必读：两个已修的真缺陷（2026-11-10 下午）

跑之前先确认这两条，否则会像第一轮一样把「环境问题」当成「预算不够」：

| # | 缺陷 | 症状 | 已修 |
| --- | --- | --- | --- |
| 1 | **系统代理拦截本机回环** | 开发机常设 `HTTP_PROXY=http://127.0.0.1:65489`，httpx 默认 `trust_env=True` 会把发往 `127.0.0.1:7001` 的请求也交给代理 → **10 次只成功 1 次、p50 181ms** | `client._http()` 与 `sidecar_bench._health()` 都加 `trust_env=False`；关掉后同一台机 10/10 成功、p50 131ms |
| 2 | **Windows 上 `wait_for` 定时器提前 ~15ms** | 175ms 的任务有 4/6 次被判超时（177ms 就抛 `TimeoutError`）→ 推理明明 180ms 完成却返回 503 `timeout`，看起来像"195ms 预算不够" | server 改为**软预算 + 硬截止**：`wait_for` 只挂 `HARD_DEADLINE_S=1.0s` 防线程卡死，预算按**真实耗时**判定（`elapsed > 195ms` 才 503） |

修完实测（两个 sidecar 同时抢 CPU 的最坏情况）：24 次请求 **23 成功 / 1 次客户端 ReadTimeout**，
成功 p50 **180ms**、服务端仅 1 条 `overtime=true`（217ms，如实 503）。

> 因此复测第一步是**重启 sidecar**：进程里跑的是启动那一刻的常量，
> 改了 `INTERNAL_BUDGET_S` / server 逻辑后不重启，测的还是旧行为。

## 1. 三种复测形态（按成本从低到高）

| 形态 | 做法 | 能得到什么 | 局限 |
| --- | --- | --- | --- |
| **A. 同机静默**（最快，10 分钟） | 关掉 IDE（Trae / PyCharm / WorkBuddy）、浏览器、其他 python 进程，再跑三步 | 排除「IDE 吃满 CPU」这一个已确认的干扰源 | 同机仍有杀软/系统更新等噪声 |
| **B. 同机容器 / WSL**（推荐，30 分钟） | 上面三样挂进容器（`-v D:/models/laya:/models/laya`），容器内只跑 sidecar + 脚本 | 接近真机部署形态，噪声少，可重复 | 容器 CPU 配额会影响绝对数字（要在结果里记 `--cpus`） |
| **C. 换机器**（最可信，1 小时+） | 搬上面三样 + 重建环境，整机空闲跑 | 唯一能作为「验收通过」依据的口径 | 权重 615MB 要拷；`D:\models\laya` 路径变了要改 `SYSTEM_ONE_MODEL_PATH` |

> 若只是要判断「195ms 预算够不够」，形态 A 就够——因为已知的唯一变量就是 IDE。
> 若要写进验收报告，用形态 B/C，并把 `--json-out` 的产物一起留档。

## 2. 三步命令（形态 A/B/C 通用）

前提：模型目录就位（`SYSTEM_ONE_MODEL_PATH` 指向 `.../laya/multilingual`；代码目录取父目录）。

```bash
# 步骤 0：起 sidecar（必须用 jev 环境；主 .venv 无 torch）
PYTHONPATH=<repo> <jev-python> -m uvicorn app.system_one.server:app --port 7001 --log-level warning
# 启动约 40s（615MB 权重 + 建图）；看到 /health 返回 200 且 model_loaded=true 才继续

# 步骤 1：纯前向基线（判断「慢是模型的锅还是环境的锅」）
PYTHONPATH=<repo> <jev-python> scripts/sidecar_bench.py --mode pure \
    --json-out eval/artifacts/a2_latency_pure.json

# 步骤 2：HTTP 全量（健康 + p95 + 成功率 + 降级）
uv run python scripts/sidecar_bench.py --mode all --requests 40 \
    --json-out eval/artifacts/a2_latency_all.json

# 步骤 3（可选）：停掉 sidecar 再单跑降级，确认 ≤250ms 且三不变量成立
uv run python scripts/sidecar_bench.py --mode degrade \
    --json-out eval/artifacts/a2_latency_degrade.json
```

`<jev-python>` = sidecar 环境的解释器（本机 `D:/Users/Alienware/anaconda3/envs/jev/python.exe`）。
`eval/artifacts/` 已在 `.gitignore` 里（原始产物不入库），把产物文件发我即可。

## 3. 判定表（脚本自己给 PASS/FAIL，不用人猜）

| 检查 | 通过条件 | 本机实测（供对照） |
| --- | --- | --- |
| `/health` | 200 且 `model_loaded=true` | ✅ 200 |
| 纯前向 p50（`--mode pure`） | ≤170ms（参考值，非硬门槛） | ❌ 183ms（IDE 占用时）/ ✅ 161ms（空闲时） |
| 快路径 p95（客户端侧） | **≤200ms**（PRD §5.3） | ❌ 268ms（含 shadow 等待，见下） |
| HTTP 成功率 | **≥90%** | ❌ 本机 0/20（IDE 占满时） |
| 降级时延 | **≤250ms** 且 `degraded=true` | ✅ 208.5ms（warm）/ 348ms（冷启首次） |
| 降级三不变量 | `intent=other` ∧ `confidence=0.0` ∧ `is_out_of_domain=true` | ✅ |

> **p95 里含 shadow 等待**（主理人 2026-11-10 定口径）：路由总耗时 = `decide_fast ≈168ms` +
> shadow 并行（`shadow_grace_s=150ms`）。所以「p95 ≤200ms」这条在 `--mode http` 下**注定难过**，
> 它真正要验的是「快路径本身是否 ≤200ms + 成功率」。若要看纯快路径数字，看 `--mode pure`。

## 5. 跑挂了怎么归因（先看这张表，别急着改代码）

| 现象 | 大概率原因 | 处置 |
| --- | --- | --- |
| 启动即 `/health` 503 `model_missing` | `SYSTEM_ONE_MODEL_PATH` 为空或指错 | 指到 `.../laya/multilingual`（不是父目录） |
| 启动报 `ModuleNotFoundError: rl_agent_api` | 只搬了 `multilingual/`，漏了父目录的 `rl_agent_api.py` | 把 `rl_agent_api.py`（及同目录依赖模块）一起放到模型目录父级 |
| 启动报 `No module named torch` | 用了主 `.venv` 起 sidecar | 换 `<jev-python>`；主 `.venv` 永远不装 torch |
| 启动报 `bcrypt` / `jwt` 缺失 | `app.core.config` 导入链带出来的 | `pip install bcrypt pyjwt`（已写进 requirements） |
| `--mode pure` 就 >200ms | 环境本身慢（CPU 少 / 被别的进程抢 / 容器配额） | 先看 `cpu_logical` 与容器 `--cpus`；本机 16 核空转时 161ms |
| `--mode pure` 正常但 `--mode http` 全 503 | 195ms 内部预算被服务层开销挤爆 | 看响应里的 `latency_ms` 分布；**不要调大 `system_one_timeout_ms`**，先回报 |
| `--mode degrade` 超 250ms | DNS/连接阶段没快失败（`localhost` 先试 `::1`） | 确认 `SYSTEM_ONE_BASE_URL` 用 `127.0.0.1`（默认已改） |
| HTTP 偶发失败但耗时只有 180ms 上下 | Windows 定时器提前触发（已修）或 sidecar 跑的是旧代码 | 重启 sidecar；确认 `server.py` 是「软预算 + 硬截止」版本 |
| 明明 `curl` 能通、脚本却大量降级 | 系统代理拦截 127.0.0.1（已修） | 确认用的是当前 `client.py`（`trust_env=False`）；不要靠设 `NO_PROXY` 绕 |
