## 2. 异常诊断

截图中的 `http://localhost:8000/health` 返回 200，浏览器控制台 `net::ERR_ABORTED` 是请求被取消（页面刷新/导航/重复请求），不是后端 5xx；前端代码没有 `/health` 调用。影响为零，无需改代码；若后续在无导航时复现，再按 Network Initiator 查 AbortController。

真正的功能缺口是：admin 只有 E18 只读，缺少写接口、状态管理、审计与前端管理页。

## 3. API 设计

保持 E18 `GET /api/rooms` 完全不动（冻结基线），新增管理端路由 `app/api/admin_org.py`（前缀 `/api/admin`，复用 `ContractAPIRoute` 错误体）：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/admin/rooms?page&page_size&room_no&status` | 房间分页列表，含床位摘要与占用数 |
| POST | `/api/admin/rooms` | 新建房间，`{room_no}` |
| PATCH | `/api/admin/rooms/{room_id}` | 改房号，`{room_no}` |
| DELETE | `/api/admin/rooms/{room_id}` | 删除房间；有床位或有设备时 409 |
| GET | `/api/admin/beds?page&page_size&room_id&bed_no&status` | 床位分页/筛选列表，含 room_no |
| POST | `/api/admin/beds` | 新建床位，`{room_id, bed_no}` |
| PATCH | `/api/admin/beds/{bed_id}` | 改床号/状态；`occupied` 不可手改 |
| DELETE | `/api/admin/beds/{bed_id}` | 删除空床；有入住长者时 409 |
| POST | `/api/admin/beds/batch-status` | 批量改状态，`{bed_ids[], status}`；任一非法整批 409/422 |
| POST | `/api/admin/beds/batch-delete` | 批量删空床；任一占用整批 409 |

错误码：重复房号/床号、删除受阻、批量非法 → 409 `CONFLICT`；空值/非法枚举/显式传 `occupied` → 422 `VALIDATION_ERROR`；不存在 → 404。所有路由要求 admin 角色；care_worker/doctor/guardian/device 一律 403（落地用 `check_roles`，见 §11）。

## 5. 后端实现

| 文件 | 内容 |
| --- | --- |
| `app/models/audit.py` | `AuditLog` ORM（ER §4.4.6 字段） |
| `app/models/organization.py` | `Room.room_no` unique；`Bed.status` 注释/CHECK 支持 disabled |
| `app/services/audit_log_service.py` | `record_audit(session, …)` 只 add+flush，不 commit；detail 存 before/after |
| `app/services/org_status.py` | 纯函数 `aggregate_room_status(bed_statuses)`：无床 available；全维护/停用 maintenance；全占用 full；有占用或非可用 partial；全可用 available |
| `app/services/org_service.py` | 房间/床位 CRUD、分页筛选、批量、事务与唯一冲突映射；唯一写库层 |
| `app/services/elder_service.py` | E19 `assign_bed` 换床后调用 `aggregate_room_status`，保持 rooms.status 同步（不改变 E19 语义） |
| `app/api/admin_org.py` | 薄路由：校验、权限、调 service、序列化 |
| `app/api/__init__.py` | 注册 `admin_org.router` |
| `app/api/schemas/org.py` | Pydantic 请求/响应模型 |

关键规则：
- `occupied` 由 `beds.elder_id` 派生，PATCH 显式传 `occupied` → 422；空床只允许 available/maintenance/disabled。
- 删除房间：无床位且无 `devices` 引用；有床位先提示删床位（避免 FK 500）。删除床位：`elder_id IS NULL` 且 status 非 occupied。
- 唯一冲突先 `SELECT ... FOR UPDATE` 锁房间行，捕获 `IntegrityError` → 先 `rollback()` 再 409；批量先按 ids 取全、逐条校验、任一失败不 flush，整批回滚。
- 每次写操作同事务写一条 audit_logs；批量一条审计，detail 带 bed_ids + before/after 数组。审计写失败则整笔回滚。
- 房间状态只读、由 beds 聚合；不提供手工改房间状态。

- `audit_logs` 提前 Day 9：同步 TD/ER 批次表与修订记录，避免第二套审计。
- E18 冻结：不改 `app/api/rooms.py` 与 `list_rooms_with_beds`；AdminDevicesPage 不受影响。
- PRD 原无该 FR：按修订记录新增，不伪造历史条款。
