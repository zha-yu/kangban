## 2. 资源与字段（字段行 · 全量取自 TD §3）

> 字段名、可空性、枚举取值与 TD 表定义逐字一致；Day 8 建表后与迁移文件再核对一遍。

### R1 `daily_reports` 家属日报（TD 586-598）

| 字段 | 类型 | 可空 | 取值 / 说明 |
| --- | --- | --- | --- |
| `report_id` | uuid PK | 否 | `UNIQUE(elder_id, report_date, version)` |
| `elder_id` | uuid FK→elders | 否 | 家属只能查绑定长者（FR-RPT-02，AC-13/18） |
| `report_date` | date | 否 | 采集完成或 20:00 强制结束时生成首版（PRD §4.8） |
| `version` | int | 否 | 补录生成新版本，历史保留（AC-25） |
| `status` | text | 否 | `normal` / `away_notice`（暂离告知，elders.status=away） |
| `summary_text` | text | 否 | 摘要，不含私密记忆/原始对话/音频；含固定声明「教学模拟信息，不构成医疗诊断」 |
| `medication_stats` | jsonb | 否 | 用药四类分别统计（§2.1 自裁 S-01 定其内部结构） |
| `audio_url` | text | 是 | TTS 语音条地址（FR-RPT-04 P1），P0 恒为 null |
| `pushed_at` | timestamptz | 是 | 通知时间 |

### 2.1 `medication_stats` jsonb 内部结构（自裁行 S-01）

TD 只规定「四类状态分别统计」，未定 jsonb 键名。键名与用药回执终态**逐字对齐**（TD §4.5 终态枚举，严禁混写、不得合并为「实际漏服」，AC-13/AC-20）：

```jsonc
{
  "taken_reported": 2,        // 已服自报
  "refused": 1,               // 拒服
  "missed_unconfirmed": 0,    // 已送达未确认
  "notification_failed": 0    // 通知失败
}
```

- 四键必全，int ≥0；服务端生成，家属端只读。
- 翻案条件：用药回执终态枚举调整时同步改，且须同提交登记修订记录。

### R2 `notifications` 通知（TD 600-617，家属侧可见子集）

| 字段 | 类型 | 可空 | 取值 / 说明 |
| --- | --- | --- | --- |
| `notification_id` | uuid PK | 否 | — |
| `target_type` / `target_id` | text / uuid | 否 | 家属端只读 `target_type='guardian'` 且 `target_id=当前 guardian_id` 的行 |
| `type` | text | 否 | `emergency_health` / `sensitive` / `missed_medication` / `report_ready` / `sos`…（TD 606 开放枚举） |
| `payload` | jsonb | 否 | 通知内容（**脱敏**）；家属端常用键见 §2.2 自裁 S-02 |
| `channel` | text | 否 | `inapp` / `webpush`；P0 阶段家属侧只出现 `inapp`（TD 裁决 B5） |
| `status` | text | 否 | `generated` / `pending` / `delivered` / `acknowledged` / `failed`（PRD §4.7 状态机；送达≠确认）。**冻结说明（2026-11-11）**：照 TD 原文 5 值冻结；X7「四态」指 AC-23 正常链路流转序列（generated→pending→delivered→acknowledged），`failed` 为失败分支终态（pending 每 30s 重试 3 次失败置 failed）；家属端 failed 分支同样要能展示（N1 模拟推送状态「失败/重试 N 次」），不得显示真实送达 |
| `is_mock` | bool | 否 | 模拟通知不计入送达率分母（TD 610） |
| `retry_count` | int | 否 | pending 每 30s 重试，3 次失败 → failed |
| `dedupe_key` | text | 是 | 幂等键（同一日报 ID+版本号只发一次，AC-25） |
| `created_at` | timestamptz | 否 | 生成时间（重试计时起点） |
| `sent_at` | timestamptz | 是 | 发送时间 |
| `acknowledged_by` / `acknowledged_at` | uuid / timestamptz | 是 | 家属端只透出展示，不提供确认端点（自裁 S-03） |
| `read_at` | timestamptz | 是 | 阅读时间；家属端唯一可写动作（N4） |

### 2.2 `payload` 家属侧常用键（自裁行 S-02）

TD 只规定「通知内容（脱敏）」。家属端卡片需要稳定键名，约定：

```jsonc
{
  "elder_name": "张桂芬",       // 展示名，不带身份证/床位明细等额外敏感信息
  "event_brief": "收缩压 185mmHg，建议联系医生",  // 一句话摘要，话术遵循 PRD「建议问医生」红线
  "report_id": "uuid|null"      // type=report_ready 时指向日报，可跳转详情
}
```

- 服务端必须按 `type` 脱敏组装；家属端对未知键**忽略不报错**（向前兼容）。
- 翻案条件：通知中心要展示更多结构化信息（如事件级别徽标）时，先在本行登记新键再消费。

### R3 `elder_guardians` 绑定（TD 385-396，家属侧范围唯一依据）

| 字段 | 类型 | 可空 | 取值 / 说明 |
| --- | --- | --- | --- |
| `id` | uuid PK | 否 | 记录编号（TD 389） |
| `elder_id` | uuid FK→elders | 否 | 与 `guardian_id` 组成 UNIQUE |
| `guardian_id` | uuid FK→guardian_accounts | 否 | 范围过滤：`WHERE guardian_id=:current AND status='active'` |
| `relation` | text | 否 | 与长者关系（绑定级非账号级） |
| `status` | text | 否 | `active` / `unbound`；本文所有接口只认 `active` |
| `assigned_at` | timestamptz | 否 | 绑定时间（TD 394） |

> 展示名（长者姓名）不在本表，服务端 JOIN `elders` 返回（对齐身份契约 S-05 的 JOIN 先例）。
> 端点返回裁剪不变（F0 只返 elder_id/name/relation，最小披露原则 S-05）；字段行先对齐 TD，端点裁剪在后续做。

## 3. 操作与判定（判定行 · 全量取自 PRD）

| 判定 | 出处 | 落点 |
| --- | --- | --- |
| 用药统计区分已服自报/拒服/已送达未确认/通知失败，不合并为「实际漏服」 | FR-RPT-01（PRD 409） | F2 `medication_stats` 四键分列 |
| 家属只能查看**绑定**长者的日报；请求未绑定长者 → **403 并记审计** | FR-RPT-02（PRD 410，AC-13/18） | F1/F2/F3 的范围过滤 |
| 日报内容不含私密记忆、完整对话、音频、未绑定长者数据 | PRD §4.8（PRD 405） | F3 只透出 §2 字段 |
| 日报固定声明「教学模拟信息，不构成医疗诊断」 | PRD §4.8 / §1.5 | `summary_text` 内携带，前端原样渲染 |
| 补录生成新版本并保留历史；每版只发一次「日报已更新」通知 | PRD §4.8（PRD 405）、AC-25 | 列表按 `report_date` 展示最新版，历史版本经 F3 可查；通知幂等由 `dedupe_key` 保证 |
| 红色事件 → 同时通知监护人（家属知情权），Mock 家属通知渠道 | FR-ALT-01（PRD 396，AC-38） | N1 列表可见 `type=emergency_health` 等记录 |
| 通知渠道：家属侧为站内 + Web Push；**无微信、无邮件**；P0 只做落库 + 演示卡片 | PRD §2.5（PRD 161）、TD 裁决 B5 | N1 `channel` 字段；P0 页面不出现推送订阅入口 |
| 送达 ≠ 确认；家属侧状态机 `generated→pending→delivered→(read)` | PRD §4.7（PRD 381/390） | N4 只写 `read_at`，不动 `status` 的 ack 分支（自裁 S-03） |
| 暂离长者日报改为暂离告知 | FR-ADM-09（PRD 443） | `status='away_notice'`，前端渲染告知样式而非常规摘要 |

## 4. 端点（自裁行 S-04：路径无文档依据，沿用身份契约 `/api` 前缀惯例）

鉴权：全部端点要求 `guardian` 主体（身份契约 S-24：主体种类不符 → 401）。`staff` / `device` 访问 → 401（种类不符），范围外 elder_id → 403 + 审计（FR-RPT-02）。

### F0 `GET /api/family/elders` — 我绑定的长者（切换器数据源）

```jsonc
// 200
{ "items": [
  { "elder_id": "uuid-a", "name": "张桂芬", "relation": "女儿" }
] }
```

- 服务端 `WHERE guardian_id=:current AND status='active'` JOIN `elders.name`（R3）。
- 只返回 `elder_id` / `name` / `relation` 三个字段（字段裁剪对齐身份契约 S-07 精神，自裁 S-05）。
- 未绑定任何长者 → 200 空数组（前端显示引导文案），不是 404。

### F1 `GET /api/family/elders/{elder_id}/reports?page=1&page_size=20` — 日报列表

```jsonc
// 200
{ "items": [
  { "report_id": "uuid", "elder_id": "uuid-a", "report_date": "2026-11-05",
    "version": 2, "status": "normal",
    "summary_preview": "今日血压偏高…",           // summary_text 前 80 字符（自裁 S-06）
    "audio_url": null, "pushed_at": "…" }
],
  "total": 14, "page": 1, "page_size": 20 }
```

- **每日期只出最新版**：同一 `report_date` 多版本时取 `version` 最大者（历史版本走 F3 按 report_id 查，自裁 S-07）。
- 排序 `report_date` 倒序；分页参数沿用身份契约 S-10（默认 1/20，上限 100）。
- 403 elder 不在绑定范围（审计）；404 elder 存在但无任何日报（仅对范围内主体）→ 返回空列表更利于前端统一渲染，**裁决为 200 空列表**（自裁 S-08）。

### F2 `GET /api/family/reports/{report_id}` — 日报详情

```jsonc
// 200
{ "report_id": "uuid", "elder_id": "uuid-a", "report_date": "2026-11-05",
  "version": 2, "status": "normal",
  "summary_text": "……（含固定声明）",
  "medication_stats": { "taken_reported": 2, "refused": 1, "missed_unconfirmed": 0, "notification_failed": 0 },
  "health_summary": "血压 152/94mmHg；睡眠 6.5 小时",   // 自裁 S-09
  "attention_events": [                                  // 自裁 S-09
    { "level": "red", "type": "emergency_health", "brief": "收缩压 185mmHg", "occurred_at": "…" }
  ],
  "audio_url": null, "pushed_at": "…" }
```

- `health_summary` / `attention_events` 不在 `daily_reports` 表内，由服务端 JOIN `health_records` 与告警记录组装（自裁 S-09，登记理由与翻案条件见 §6）。
- 403 日报所属长者不在绑定范围（审计）；404 不存在。

### F3 历史版本

F2 对任意 `report_id`（含旧版本）均可查，无需独立端点；列表不重复出旧版本（F1 自裁 S-07）。前端如需「查看历史版本」入口，用 F1 的 `report_date` + 本端点组合即可，暂不另设（自裁 S-10）。

### N1 `GET /api/family/notifications?page=1&page_size=20&unread_only=false` — 通知中心列表

```jsonc
// 200
{ "items": [
  { "notification_id": "uuid", "type": "emergency_health",
    "payload": { "elder_name": "张桂芬", "event_brief": "…", "report_id": null },
    "channel": "inapp", "status": "delivered", "is_mock": true,
    "retry_count": 0,
    "created_at": "…", "sent_at": "…", "read_at": null }
],
  "total": 3, "page": 1, "page_size": 20 }
```

- 固定过滤 `target_type='guardian' AND target_id=:current`；`staff` 侧通知对家属不可见。
- 排序 `created_at` 倒序；`unread_only=true` 时附加 `AND read_at IS NULL`。
- `acknowledged_by` / `acknowledged_at` / `dedupe_key` 不透出（家属端无消费场景，自裁 S-05 同源）。
- 模拟推送状态展示（FR-RPT-03）：前端用 `is_mock` + `status` + `retry_count` 渲染「模拟推送 · 已送达 / 重试 2 次 / 失败」，不得显示真实发送/送达（PRD 390）。

### N4 `POST /api/family/notifications/{notification_id}/read` — 标记已读

```jsonc
// 200 { "notification_id": "uuid", "read_at": "…" }
```

- 幂等：重复调用返回原 `read_at`，不更新时间。
- 403 通知不属于当前家属（审计）；404 不存在。
- 只写 `read_at`，不改 `status`（自裁 S-03：家属端 P0 无确认语义，ack 留给员工侧 HITL）。

## 5. 错误码

外壳与码表完全沿用身份契约 §7（`detail` / `code` / `trace_id`）。本文新增的触发场景映射：

| 码 | 本文何时 | `code` |
| --- | --- | --- |
| 401 | 主体不是 `guardian`（种类不符，S-24）；凭证失效 | `TOKEN_INVALID` 等，同身份契约 |
| 403 | elder_id / report_id / notification_id 超出家属授权范围（**必审计**） | `SCOPE_FORBIDDEN` |
| 404 | 范围内资源不存在 | `NOT_FOUND` |
| 422 | 分页参数越界、uuid 格式错 | `VALIDATION_ERROR` |

> 家属端不产生 409 / 400 的新场景；如出现按身份契约通用口径处理。

| S-05 | 响应字段裁剪 | F0 只返 3 字段；N1 不透出 `acknowledged_*` / `dedupe_key` | 最小披露原则（PRD §1.5 隐私边界：家属不看他人数据；冗余内部字段徒增耦合） | 前端出现真实消费场景时按 §6 流程放开 |
| S-06 | 列表摘要截断 | `summary_preview` = `summary_text` 前 80 字符 | TD 无列表字段规范；375px 列表卡片两行内可完整展示 | 详情页下放全部内容，不受此限制 |
| S-07 | 列表只出最新版 | 同 `report_date` 取 `version` 最大者 | PRD 405「补录生成新版本并保留历史」未规定列表聚合方式；家属关心的是「今天这一天」，版本是审计概念 | 前端要做版本对比视图时改为全量出 |
| S-08 | 无日报返回 200 空列表 | F1/F0 空结果一律 200 + 空 `items` | 404 语义留给「资源本身不存在」；「还没有数据」是正常态，前端可统一渲染空态引导 | — |
| S-09 | 详情组装字段 | `health_summary` / `attention_events` 由服务端 JOIN 组装，不落 `daily_reports` 表 | PRD 405 要求日报含健康摘要与需关注事件，但 TD 586-598 表内无承载字段；生成时快照 vs 查询时组装两者皆可行。选**查询时组装**：避免第二套快照存储与补录版本快照一致性问题；代价是详情接口多两个 JOIN | 评审要求「日报打开即当时快照」（补录后摘要不随后续健康记录变化）时，改为生成时落库并在本行登记翻案 |
| S-10 | 历史版本入口 | 复用 F2 按 report_id 查，不设独立端点 | F2 天然覆盖；页面方案 §3.3 未要求版本切换 UI | 页面方案新增版本对比需求时再议 |
| S-11 | Mock 开关方式 | 前端 `api.ts` 内 `USE_MOCK` 常量 + 按本文结构内置数据；切真实接口时删 mock 分支 | 前端先行的临时桥，不进环境变量体系（避免被误配置成「永远 mock」） | 后端 Day 8 联调通过后删除，同提交登记 |
