## 现象（2026-11-06 W6 实测中发现）

Day 4 前端联调种子设备 `33333333-3333-3333-3333-333333333333`（secret 为
sha256 可复算的固定值 `demo-device-secret-2026`）在种子写入后数分钟内，
DB 中 `token_hash` 被改写为未知值（`299d7798…`），导致登录 401。

- 轮换后设备仍 `bound + online`——完整序列应为「解绑（轮换）→ 重新绑定」
  或测试脚本直写 DB；单纯的 unbind 会留下 `elder_id IS NULL + offline`。
- 全库唯一轮换点：`device_service._clear_binding()`（unbind / bind(null)），
  需 admin 权限（E9/E10）。
- 轮换发生窗口内跑的是旧 uvicorn 进程，日志在同事终端，无法追溯。

## 待办

1. 问 A2/E 组：11-06 上午谁在测设备绑定/解绑流（console 端 E9/E10 或脚本）
2. 确认是否存在绕过 admin 校验直写 devices 的测试脚本；有则收口
3. 复核 `_clear_binding` 的审计日志是否落了 `audit_logs`（若落了，直接查表
   定位操作者；没落则补——这正是它该起作用的地方）
4. 种子设备 secret 若再被轮换，重置方法：sha256("demo-device-secret-2026")
   = `34fb8189f343abf728ea5a95724aeea6fe27aa974aca3ace8b418ea357b556f0`，
   UPDATE devices 对应行即可

## 验收

- 能说清轮换来源（人或脚本），或确认属正常测试行为
- `audit_logs` 中可查到该次 unbind/bind 操作记录（缺失则补齐）
